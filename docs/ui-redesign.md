# 住民を見守るUIの再設計

2026年11月3日。ユーザーから「ボタンが何をするのか分からず、ゲームらしいUIにもなっていない」と指摘があったため、HUDと提案の流れを作り直す。人物の更新とは別に、UIを最優先の受け入れ対象へ戻す。

## 直す問題

以前は、選んだ人物を右端へ、相手の選択と実行ボタンを画面下へ離して配置していた。「話す機会」「手助けを相談」では、誰が誰へ何を提案するかが分からない。人物情報は長い文章と同色のゲージへ並び、行動への返答は短時間の通知へ流れた。「疲れ」「空腹」のゲージは増えるほど悪い一方、願いの進捗は増えるほど良く、読み方も統一していなかった。

## リサーチから採った判断

[The Sims 4公式マニュアル](https://eaassets-a.akamaihd.net/eahelp/manuals/the-sims-4-xbox-one-na.pdf)は、選択人物、現在と今後の行動、時間操作、人物の詳細を役割別の領域へまとめている。このゲームでも、人物への操作と町全体への操作を分け、時間の操作を独立させる。直接人物を操作するThe Simsと異なり、本作では提案への返答を住民が選ぶため、返答と次の実際の予定を重視する。

[NN/gの認識と想起の解説](https://www.nngroup.com/articles/recognition-and-recall/)を参考に、操作名を覚えさせる短い名詞ボタンから、対象と動作が見える選択へ変える。ツールチップを読まないと目的が分からないボタンを主要操作にしない。[状態の可視化の解説](https://www.nngroup.com/articles/visibility-system-status/)を参考に、停止状態、選択人物、提案の相手、返答、予算を操作した場所で確認できるようにする。

これらは設計上の判断であり、このUIが初見で理解できることを実証した結果ではない。

## 新しい操作の流れ

1. 町の人物、または顔と名前の付いた住民一覧から一人を選ぶ。
2. 左下のカードで名前と今の行動を見て、「この人を追いかける」で近くへ寄る。
3. 「咲に提案する」のように本人を示すボタンから、休息・願いへの応援・会話・手助け・共同制作を選ぶ。
4. 二人の提案は相手を選ぶ。肖像、双方の名前、手伝う方向、実行する内容を確認してから送る。相手の選択だけでは提案しない。
5. 同じ画面で住民の返答を読む。具体的な会話の別案がある場合は、実際の日時・場所・相手を表示し、合意して初めて約束する。
6. 「町に戻る」で提案前の時間状態へ戻る。読む間に町の時間は進まない。

人物手帳には、今の願い、人間関係、思い出、家計と仕事をまとめる。「約束の一覧」には近い約束から後日の約束まで日時順に残し、提案した時間を後から探せるようにする。最近の出来事と、人生の節目を振り返る町の記録は別にする。開いた引き出しは同じ場所の「閉じる」またはEscで閉じられる。

元気・満腹・交流のゲージは、いずれも満ちるほど満たされた状態を表す。低いときは色も変える。文字の説明を常設して埋めず、数値はホバーで確認する。

時間の速さを変えても停止中は停止を続ける。「時間を進める」で再開する。町の整備は別の入口にし、予算とベンチの費用を同じ場所に置く。配置中はプレビュー、置ける場所の色、キャンセルを表示する。置けない場所を押した後も位置を選び直せる。

## 表現と確認

紺の文字と操作部、紙色の手帳、真鍮色の枠を共通テーマへまとめる。肖像を人物の手がかりにし、押せるボタン、選択されたタブ、入力欄、キーボードのフォーカスを区別する。アイコンには意味の分かる文字を添える。

1280×800と1440×900で、主要操作の到達、領域の重なり、提案から返答と別案の確認、停止状態の復元、背後への入力漏れ、配置の取消しを確認する。実行ログと実画面は [UIの確認記録](verification/ui-redesign/)へ保存する。SHAは出自情報に限り、検査の件数や合否には含めない。

次の人による試遊では、説明なしで「人を選ぶ」「近くで見る」「止める」「相手を選んで提案する」「返答と次の予定を説明する」を試す。自動入力の成功や画像の目視だけで、分かりやすさと面白さの受け入れを完了扱いにしない。

## Macのカメラ操作

配布版を短く遊んだユーザーから、トラックパッドだけではズームできないという報告を受けた。11月4日の実装では`InputEventMagnifyGesture`で拡縮、`InputEventPanGesture`でパンを行い、画面の右下へ「−」「町の全景」「＋」を置いた。キーボードの＋/−と従来のホイールも同じ拡縮処理を使い、手元まで近づける距離へ変更した。

住民一覧・手帳上や提案画面・メニュー中の入力を背後の町へ通さない。停止中もカメラは動かせ、全景ボタンは追跡を解除して町へ戻る。合成したエンジン入力では、倍率、上限下限、UIの遮断、停止の維持、1024/1280/1440幅での操作部品の範囲を確認した。

配布版のボタン操作と、物理トラックパッドから届くピンチ/パンは別に記録する。物理デバイスで全景と近景を行き来する受け入れは継続課題とし、合成入力の成功で代替しない。
