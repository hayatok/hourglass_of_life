# 検証記録の扱い

現在の事実と未確認点は [current-status.md](current-status.md) だけにまとめる。過去の版ごとのログ・画像・巨大JSONは作業ツリーから削除し、必要な場合だけGit履歴を参照する。

- 動作、状態変化、接触、描画、保存再開を確認する。SHA・ハッシュは識別情報に限り、検査の合否・件数に含めない。
- 単体確認、実ゲームでの連続動作、人による操作、配布物の確認を分ける。自動確認だけで自然さや面白さを受け入れない。
- 終了コード0だけでなく、SCRIPT ERROR/ERRORと完了表示も読む。関係する確認から順に行い、変更がないのに重い検証を繰り返さない。
- 出力は無視対象の `builds/` または各素材の `review/` へ生成する。原本や後工程が読む入力は `assets/` の `source/`・`production-inputs/` へ置く。
- 必要な最新結果だけを残し、失敗の反復ログ・古いレンダー・重複ビルドを積み上げない。

この整理はゲームの完成や未完了動作の合格を意味しない。
