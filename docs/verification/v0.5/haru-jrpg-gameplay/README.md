## モデルと描画で確認したこと

見えている晴のメッシュが新しい `CH_Haru.glb` 由来で、旧モデルや仮メッシュではないことを確認した。元の生成GLB、導入GLB、manifestのSHA256を照合し、実際に使うアルベドのRGBA8画素も元の埋め込みJPEGと一致した。実スキンの接続、35本の骨、9クリップ、アダプターの契約エラー0を実際の町の人物で検査した。

移動中の骨の回転差は0.295rad、足のローカル位置差は0.226m、GPUで読み戻したメッシュ頂点の最大変位は0.463mだった。同じ区間でシミュレーションと描画人物の位置も動く。共同作業では左右の手首が既存の作業対象へ届き、食事の腰・カップ、睡眠の頭・骨盤も実家具の接触位置へ合う。

晴の顔は **Blink / TiredEyesの2制御**。自然な睡眠では実シェーダーのblinkが1、起床後は0になり、接写でも閉眼と開眼を確認した。疲労値も本人の実状態から届く。口の動き・Smile・虹彩の視線・髪の加齢は未実装。骨による頭の向きと手振りは動く。

通常の会話画面では晴の名前だけが頭上に表示され、相手の顔・手元が他の名前で隠れなくなった。右欄の肖像も新モデルへ更新されている。頭上文字は16mより近い距離で大きさを抑え、顔の接写でも目や手元を圧迫しない。通常画面と接写は同じ名前表示処理を使い、その処理は人物や時間を進めない。作業や食事は通常の追従角度で背中側になるため、制作の補助画像はカメラだけを前へ動かした。同じ14:52の実作業で、相手・顔・両手とラジオを確認できる。

選択中の晴はLOD0を維持する。この記録のソース指紋には3段階のGLB、眼のlayoutとshader、portrait、main、人物・接触コードを含める。LOD1/2の距離切り替えと眼の値の維持は、別のアダプター・LOD検査で扱う。

道具ごとの指先の修理動作、着席・起床の滑らかな移り変わり、衣服・寝具の干渉、混雑時の身体の重なり、夜の見やすさは継続課題。この確認は実ゲームの自動進行とGPU出力の検査であり、人によるプレイテストや面白さの実証ではない。
