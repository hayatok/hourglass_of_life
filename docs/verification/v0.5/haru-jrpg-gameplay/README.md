2026年11月3日。Godot 4.7.2 / macOS / Apple M5 / Compatibility。通常の12人の町をseed 711から進め、晴の行動や相手を書き換えずに観察した。現在の記録はr3のLOD、新しい目のシェーダー、肖像、選択中の人物だけの名前表示を含む。共通の目の制御には追加UVチャートへの対応を加えたが、晴のr3本体は変えず、既定の2チャート・compress方式を維持する。[r1の中間記録](r1-static-atlas/review.json)も残す。

headlessは **37件成功・失敗0（49.711秒）**、GPUは **38件成功・失敗0（24.378秒）**。エラーログなし。実描画でスキン変形を調べる1件だけがGPU側に加わる。[headlessの結果](gameplay-headless.json)、[GPUの結果と時刻・技能・接触値](gameplay.json)、[機能と画像の確認記録](review.json)に保存した。件数は動作・実スキン変形・日課・接触・眼・保存再開の確認だけを数え、SHAやハッシュの照合は合否と件数に含めない。今回の実行時間は他の制作処理が動いていた環境での値であり、性能比較には使わない。

## モデルと描画で確認したこと

見えている晴のメッシュが新しい `CH_Haru.glb` 由来で、旧モデルや仮メッシュではないことを確認した。表示中の顔・髪・衣服のテクスチャをGPU画像で目視した。実スキンの接続、35本の骨、9クリップ、アダプターの契約エラー0を実際の町の人物で検査した。

移動中の骨の回転差は0.295rad、足のローカル位置差は0.226m、GPUで読み戻したメッシュ頂点の最大変位は0.463mだった。同じ区間でシミュレーションと描画人物の位置も動く。共同作業では左右の手首が既存の作業対象へ届き、食事の腰・カップ、睡眠の頭・骨盤も実家具の接触位置へ合う。

晴の顔は **Blink / TiredEyesの2制御**。自然な睡眠では実シェーダーのblinkが1、起床後は0になり、接写でも閉眼と起床後の開眼を確認した。現在の起床接写はまぶたが少し下がった描画で、虹彩が見える。起床時点の状態記録はblink=0で、その後の描画サンプリングも続けている。疲労値も本人の実状態から届く。口の動き・Smile・虹彩の視線・髪の加齢は未実装。骨による頭の向きと手振りは動く。

通常の会話画面では晴の名前だけが頭上に表示され、相手の顔・手元が他の名前で隠れなくなった。右欄の肖像も新モデルへ更新されている。頭上文字は16mより近い距離で大きさを抑え、顔の接写でも目や手元を圧迫しない。通常画面と接写は同じ名前表示処理を使い、その処理は人物や時間を進めない。作業や食事は通常の追従角度で背中側になるため、制作の補助画像はカメラだけを前へ動かした。同じ14:52の実作業で、相手・顔・両手とラジオを確認できる。

選択中の晴はLOD0を維持する。LOD1/2の距離切り替えと眼の値の維持は、別のアダプター・LOD検査で扱う。

道具ごとの指先の修理動作、着席・起床の滑らかな移り変わり、衣服・寝具の干渉、混雑時の身体の重なり、夜の見やすさは継続課題。この確認は実ゲームの自動進行とGPU出力の検査であり、人によるプレイテストや面白さの実証ではない。

## 出自の記録

元の生成GLB・導入GLB・manifest、実行時アルベドの画素、3段階のGLB、眼のlayoutとshader、肖像、main、人物・接触コードのハッシュは、JSONの `provenance` に記録する。ファイルを識別して後から経過を追うための情報であり、機能検査の合否を決めたり、成功件数へ加えたりしない。従来数えていた出自照合5件は各実行の件数から除外し、穴埋めの検査は追加していない。

共通眼runtimeの対応範囲は[集計記録](../../../../assets/models/jrpg-resident-renewal/saki/review/texture-eyes/cast-summary.json)に記載する。[旧・新シェーダーの画像識別記録](../../../../assets/models/jrpg-resident-renewal/saki/review/texture-eyes/haru-image-regression.json)には、同じr3の形状・姿勢・カメラ・照明による6枚のPNGと、74d4c6cのLOD1/2画像との差を残す。これらのハッシュ照合も検査件数には含めない。新3人の原型の眼と契約の記録は、身体を実町へ導入した検査とは分ける。
