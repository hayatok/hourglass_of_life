# 天候が自由時間の選択へ影響する初期実装

2026年11月4日。通信しない架空の気候を使う開発版。実測統計や現在の天気予報ではない。

## 実装

`data/weather.json` と `WorldWeather` で一季節3日・一年12日の晴雨・気温を進める。住民の判断用とは別の乱数、天候区間と次の切替、暦の対応を保存する。schema8のみを受け入れ、読み込み前に町の時計との整合を検査する。HUDや照明の更新で乱数を消費しない。

自由な休息・食事・交流・趣味・写真・記録を読む候補に、現在の雨、気温、予想される屋外時間、本人の特性から有限の負担を加える。屋根は実際の部屋の境界と活動スポットから判定する。屋内でも、そこまでの外出負担は残る。移動時間は直線距離による採点用の見積もりで、実際の移動は既存の道路・室内通路・家具回避を使う。町外の未制作の室内は判定不明として評価しない。

現在の天候を小さな町で直接知覚できるという仮定を置く。未来の天候や他人の私的状態は候補に渡さない。勤務・日課・先約、交流中の状態、切迫した空腹・疲労は採点より前に処理する。共同制作や盤遊びの誘いの場所変更・延期、体の濡れや温熱欲求、服装、傘、雨粒、物価・雇用・ニュースはこの初期実装には含まない。

## 条件比較

[行動の比較](behavior.json)は7人×128個の同じ判断用seedについて、同じ保存した人物・予定・家計を毎回復元し、その時点の晴れ/雨だけを変えた896組。新しい計画の提案はこの比較中だけ先送りした。341組で実際の活動または行き先が変わり、屋外選択は晴れ116回、雨87回だった。小標本12seedでは逆方向に出たため、初期の12件だけを傾向の根拠には使わなかった。雨でも屋外を選ぶ余地を残している。

変更した一例では、選択後に実際の `_assign` が作る経路を `_move` で最後までたどり、屋内の目的地へ到着した。これは移動処理の確認で、時間経過を含む自然発生の試遊とは分けている。

途中の町を実ファイルへ保存し、天候・人々・二つの乱数・約束・物を復元して、同じ先の経過になることも比較する。数値はJSON保存時の丸めを許容し、乱数の文字列はそのまま比較する。表示用の状態や識別用のSHAを、これらの動作確認の代わりにしない。

## 描画と画面

[GPUの記録](presentation-gpu.json)は実際のmain sceneへ晴雨の表示用snapshotを渡した比較で、自然発生の雨や行動の証拠ではない。1440×900、1280×800、1024×700で日付・天候・時計・上部ボタンの非重なりと文字幅を確認した。雨天に応じて日光・環境光・空の色を変更する。反復更新で暗さが累積せず、夜の明るさの下限を保つ。
