# 布小物を作り、見せて収納する

2026年11月4日。[Issue #21](https://github.com/hayatok/hourglass_of_life/issues/21)の初期実装。12人の暮らしに、有限の材料と実道具を使う制作を追加した。

布6枚、はさみ・針・糸巻きを町の物として持つ。同じ布のIDで、取り出し→運搬→裁断→縫製→完成品の提示→収納へ進む。材料費は実際の裁断開始時に一度だけ支払い、技能と成果は最後の縫製で反映する。相手が実際に完成品を見てから、その作品に結びついた記憶を残す。

途中品と未提示の完成品は所有者の物として優先して再開する。相手や教わる側が変わっても所有者を変えず、前払いした物の再開には新しい材料費を要求しない。次の約束には、残る作業だけでなく、工具を戻す・見せる・しまう時間と実経路を見込む。

提案画面で制作の種類を選び、実行前に双方の名前と「布小物づくり」を表示する。住民カードは今の工程を、人物手帳の暮らしの頁は所有する完成品と途中品の数を示す。

## 工程と保存

[実Simの統合確認](integration.json)は、制御した12人の町による379項目。人物の初期位置と技能を維持し、日課・新しい自律提案・切迫した欲求はfixtureで制御した。全工程と工具の準備・操作・返却で実ファイルへ保存し、町を進めてから読み込み、人物、時計、乱数、家計、約束、物、記憶を比較する。schema9を使い、旧開発版は移行しない。

勤務・空腹による中断と同じ途中品の再開、完成直後に中断した物を見せるだけの再開、双方の所持金0、別のlearnerとの再開を含む。次の約束の出発が片付け前に入らず、実際の収納完了が所要時間の見積もり内になることも確認する。収納6箇所から机・家まで24経路を5cm刻みの独立した幅判定と実際の移動で確認した。

## 自然な町の経過

[自律進行の比較](autonomy.json)は12人・10seed・12代表日、介入なしとラジオを一度提案した場合の比較。介入なしでは、完成した巾着を相手に見せて収納した物が計13点あった。2seedでは布小物が発生しておらず、全員に同じ行動を強制する設計ではない。これは架空の行動ルールの観察で、人間行動の学習や面白さの実証ではない。

[自然な制作の保存位置](natural-capture.json)はseed711・1447分、結衣が智と縫製中の町。`tools/inspect_sewing.gd`で欲求・予定・技能・参加者・乱数を変更せず取得した。完全な保存ファイルはローカルに保持する。

最初の[不足判定](natural-eight-failure.log)は旧テストの既定人口8人を使っていた。現行の開始人口12人へ合わせて再観察した結果が上記であり、8人の記録を12人の証拠には使わない。

## 手元と画面

[headless](presentation-headless.json) / [実GPU](presentation-gpu.json)は実際のMainを使う制御fixture。各24項目で、連続する全工程、9物体の一意な描画、制作途中の保存・復元、接触を確認する。画像が書けたことと機能の成否は分けている。

はさみは実形状の輪の接触点、針は直径4mmの把持部へ、指の計測点を合わせる。遠位4mm帯の頂点重心、または実三角形上の人差し指側面を使う。GPUの約0.002mmという値は計測点から目標点へのIK誤差で、肌の表面への接触精度ではない。遠位重心は曲面の内側にあり、実mesh表面の確認を別に行う。実表面の測定では、晴の指が太腿へ結ばれた不正なウェイトも検出した。運搬の掌と左支持の掌は骨のrestから求める接触目印であり、掌全体のスキン変形の測定ではない。左支持の基準面は実際の布meshとの三角形交差から求める。体勢を整える間と完成時に手を離す間は支持中として計測しない。保存からの最初の描画では制作中の体勢を復元し、初期姿勢からの補間で保持中の工具を手から離さない。

[裁断](cut.png) / [縫製](sew.png) / [完成品を見せる](show.png) / [取り出し](take.png) / [収納](store.png)。静止画は各姿勢の目視用で、滑らかさや人による試遊の代わりにはしない。

[体格ごとの確認](rig-contacts.json)は、現住民のうち制作対象の11人と12歳の成長後の凛、計12rig・裁断/縫製各3進捗。実Simの提案から各工程へ進め、時計を固定して姿勢を落ち着け、計測点と表示された工具の面への距離を6mm以内で確認した。凛の12歳は明示したfixtureで、5年の自然経過ではない。旧モデルは実三角形から測った人差し指の側面も使い、回転量の上限を変えずに工具を持つ。独立したskin probeが、`skeleton_updated`内の最終姿勢と全ウェイトから、表示中LOD0の指の実三角形を変形する。工具面からの符号なし最短距離も別に6mm以内で確認し、計505項目を通過した。これは一定の接触帯の確認で、手や衣服全体の貫通判定ではない。

[提案UIのheadless](proposals-headless.json) / [GPU](proposals-gpu.json)は各75項目。1024×700で実際のレシピメニューをSpaceで開き、Enterで選ぶ操作、世界を変えないプレビュー、ボタンの名前、メニューの画面内配置と終了を確認した。メニュー選択直後のウインドウフォーカス復帰と、`close_panel`の同期的な終了を分けて確認する。

[エンジン検証の一覧](all-engine-checks.json)は44本のheadlessスクリプトと今回の関連GPUを、複数の直列実行からまとめたもの。一続きの全件実行の記録ではない。制作が45分の経過だけで完成するとした旧テスト、保存時に勤務で町外にいる結衣へ可視meshを要求した旧テストは、実工程・実際の可視性を確かめる形へ修正して再実行した。

晴は指へ混入した太腿の影響だけを、LOD0/1/2の78/51/17頂点から除いた。位置・UV・法線・クリップ・画像は保持し、指と手の正当な影響を正規化した。元の配布モデルとmasterは退避・保持し、[新しいBlender authoring copyとclean reimport](haru-master-roundtrip.json)も確認した。再現用ツールは`tools/repair_haru_finger_weights.py`。このデータ作成・同期と、上記の実ゲーム接触の成否は別に記録する。

## Mac版の起動と保存再開

`builds/playable-sewing-20261104/`にUniversalアプリとZIPを出力した。[出力記録](build-record.json)のソース版は識別情報。[最終アプリ内のPCK](packaged-ui.json)をソース参照できない場所から読み込む35項目を通過した。

最初のチェックポイント版では、自然な12人の町の13:07の保存を読み込み、[縫製中の結衣](native-sewing-paused.jpg)を追跡・画面ボタンで拡大して確認した。その後の実アプリで、14:09の智との制作記録と人物手帳の完成した巾着1点・作りかけ0点を確認し、16:44にメニューから保存した。[実際に書かれた状態の抜粋](native-save-summary.json)は同じ作品の所有者・完成・提示先・収納先を記録する。ネイティブ操作中の短い提示モーションは捉えられておらず、その連続描画の根拠は上記のMain/GPU実行である。

手帳に完成品とは無関係な町の集計「制作0%」が並ぶ問題を修正し、アプリを再ビルドした。最終版で16:44の保存を再読込し、16:48に一時停止して[完成品の保持と手帳表示](native-owned-after-load.jpg)、[実際のレシピ選択と二人の名前](native-proposal-recipe.jpg)を確認した。提案は確定せず閉じ、時計の停止を確認した。終了後に元の二つの利用者セーブを復元し、確認用アプリは終了した。最終起動ログにエンジンのエラーはない。これはエージェントによる実アプリ操作で、人の初見試遊、物理トラックパッド、Intel実機の確認ではない。

GitHub Actionsの[初回実行](https://github.com/hayatok/hourglass_of_life/actions/runs/41773464503)は新しい制作4本を通過した後、88年を進める寿命テストが35年以降で600秒の制限に達した。ローカルでは同じ寿命テストが503秒で50項目を通過している。寿命テストだけ上限を1800秒へ変更し、88年の経過、完了マーカー、エラー判定は維持する。CIの結果はローカルの合格記録と別に追跡する。

## 続けて作るもの

現在は巾着一種類と初期布6枚で、入荷・用途・贈り物・衣服・教える側の実演や役割交代は未実装。空腹や勤務での緊急中断は安全な収納へ即時退避し、通常完了と同じ片付けモーションにはまだなっていない。接触は全衣装・成長段階での品質保証ではなく、人による初見の操作・見守る楽しさの受け入れも残る。

次は[ロードマップ](../../development-roadmap.md)に沿い、自律性・有能感と、教わる・自分で進める・手伝いを断る選択をこの実物の制作へつなぐ。SHAやハッシュは素材・ビルドの識別情報に限り、機能の合否・件数へ含めない。
