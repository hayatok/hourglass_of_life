# 命の砂時計の開発計画

完成目標は、個性と生活歴の異なる住人が自律的に暮らし、出会い、協力、すれ違いから町の暮らしが変わるJRPG調3Dの人生シミュレーション。初期の8人を足場に12人、16人、24人へ段階的に増やし、住人の組合せ、経験、関係、環境によって、遊ぶたびに異なる展開が生まれるゲームとして仕上げる。

プレイヤーは気になる人を見守り、場所、予定、道具、負担の分担に働きかける。住人も自分から誘い、相談し、学び、断り、別の方法を考える。個人の選択が別の人の機会や判断を変え、その積み重ねが習慣、集まり、作品、進路、継承へつながることを面白さの中心に置く。

Godot 4.7を使用する。町、住人、家具、UI、アニメーションを保存されたシーンとリソースに分け、シーンエディタで配置や調整ができる構成にする。画像資料をゲーム画面の代わりに置かず、実際の3D空間で住人が移動して行動する。

## 現在地と今後の順序

2026年11月4日に計画を更新した。v0.1〜v0.4で日常、関係、仕事と家庭、年月の基盤を作り、v0.5では人物・家具・町の表現を制作している。v0.6では共同活動の定義、個人の知識、状況別の経験学習、自発的な共同作業に加え、日課を避けた将来の約束と、自分から家事・世話の支援を頼む計画を接続した。画面の折り畳みと遠景人物の簡略表示も実装した。[検証と未完了の範囲](verification/v0.6/README.md)を記録する。v0.5とv0.6全体の受け入れは継続中であり、人数や試験条件は開発の目安とする。

HUDと提案の流れは作り直し、住民カードから対象・相手・内容・返答へつなぐmacOS開発版を用意した。[再設計とリサーチ](ui-redesign.md)と[配布アプリの操作記録](verification/ui-redesign/playable-20261103/)を残している。その後のユーザーの実プレイで、モデルの品質、Macのトラックパッドでズームできないこと、内面のパラメータと行動の薄さが指摘された。今回の改訂では、操作の不具合、人物の見た目、欲求から選ぶ行動を次の優先事項にする。現行版の品質受け入れを完了扱いにしない。

| 優先 | 次に変えること | 確かめてから進む条件 |
|---|---|---|
| P0 操作 | Macのピンチ拡縮、トラックパッドの移動操作、画面上の拡大・縮小とキーによる代替。リストや提案画面への入力と分離 | 書き出したmacOSアプリをトラックパッドだけで使い、全景と顔の近景を行き来できる。UI上のスクロールで背後のカメラが動かない |
| P0 人物表現と相互作用 | 新4人の顔・輪郭・セル塗り・照明・動作を実画面で仕上げる。取る・持つ・運ぶ・扱う・置く共通工程と街の物を接続し、会話・遊びにも番と反応を用意。旧8人との混在を解消 | 元画像と実際の町を比べ、近づくところから片付け・退出まで連続して確認。誰が何を持ち、何をして、物や相手がどう変わったかを読み取れる |
| P1 世界と暮らし | 季節・晴雨・気温で自由時間の選択と移動を変え、一着の実形状の上着と収納・濡れ・乾燥へ接続。続いて限定費目の物価・在庫・雇用・地域の出来事 | 同じ人物・予定・判断seedで世界条件だけを変え、準備・選択・実移動・支出・交流の違いを確認。勤務や先約を天候の都合だけで破棄しない |
| P1 内面と行動 | 既存4欲求の共通管理、自律性・有能感・刺激、短期気分。一人の回復、静かな同席、練習・教え合いをセットで追加 | 状態を変えると行動と実際の充足・負担が変わり、暮らしの責任と経験へつながる |
| P2 私生活と相互作用 | 安心、承認、貢献、相手別の親密さ、成人の性欲などの隠し状態と、相談・関係の選択・双方が望む私的な時間 | 各人の意思・境界・異なる受け止めを保ち、誘う・断る・延期・中断がその後の暮らしを変える |
| P3 連鎖と人口 | 12人で欲求・経験・紹介・集まりを確かめ、その後16/24人へ | 人数や行動量だけでなく、別の人の機会、続く習慣・作品・人生に違いが残る |

P0同士は独立して進められるが、重い制作・描画・検査は一つずつ実行する。以下の新しい欲求と行動は設計段階であり、今回の文書更新でゲームへ実装したとは扱わない。

共同制作と話題の人物IDによる分岐は活動定義へ移した。増員に合わせ、次の願い、肖像と外見、世帯・仕事・人生条件も定義から読める構成へ広げる。初期8人の生活上の固有処理は残る。[行動モデル設定案](../data/behavior-model.json)全体は実行コードに接続されていないため、資料への追記と実際の思考ルーチンの変更を区別する。

最初の10seed比較で多かった見送りに対し、食事・休息の準備、個別の移動、最大二回の再相談を接続した。当初の日時での参加と、予定変更後の参加を分けて同じseedで比較し、相談案件の完了が増えたことを確認した。実会話での紹介から後日の協力へつながる一例も、同じプレイの記録で追った。次は経験による選び方と理由の読み取りやすさ、教わった人から別の人への協力、複数人の集まりを検証する。約束や誘いの繰り返しと生活の負担も引き続き調整する。

住民同士の接点を増やすため、v0.8の人口拡張の一部を前倒しし、12人の町を先に検証する。新しい4人には、写真や模型を楽しむ午前勤務の図書館員、早番の修理補助、午後に受注作業をする縫製職、午後の音楽講師という異なる生活と技能を与える。既知の関係は少数から始め、初対面の相手の技能を町全体で共有しない。住まい、寝床、食事の席、通路を同時に用意する。

8人と12人の無介入経過では、交流の総数に加え、一人当たりの交流、相手の偏り、新旧住人の接点、仕事・食事・休息の負担を分けて見る。人数が増えても、同じ相手への集中や誘い直しだけが増える場合は、16人へ進む前に生活時間、場所、誘いの条件を調整する。v0.5〜v0.7の未完了項目は維持し、人数だけで版の完成とはしない。

| 版 | 中心となる要素 | 完了を判断する体験 |
|---|---|---|
| v0.1 日常ときっかけ | 8人の日課、移動、観察、提案と返答、利用可能な場所 | 人物を選び、その事情に合う働きかけと反応を確かめられる |
| v0.2 関係と記憶 | 方向のある関係、共同体験、約束、別案、習慣 | 同じ操作でも相手と過去の経験で結果が変わり、それを説明できる |
| v0.3 仕事と家庭 | 収入、仕事の喜び、家事や世話、支援、個人の目標 | 人柄だけでなく生活の条件によって選択が変わる |
| v0.4 年月と人生 | 加齢、転居、退職、願いの変化、継承と別れ | 時間の区切りが行動を変え、誰かの経験が町に残る |

| v0.6 個性と経験から選ぶ | 行動の部品化、本人が知る情報、短い計画、状況別の学習。公開・非公開の欲求、短期気分、活動別の充足と負担 | 同じ人物でも内面・経験・状況で選択が変わり、同じ状況でも人物ごとの理由がある |
| v0.7 人と人から展開が生まれる | 住人発の誘い、紹介、教え合い、分担、約束の修復、集まり。親密さと成人の私的な動機、双方の意思 | 固定ペアの指定がなくても、異なる欲求や受け止めから出会い・協力・延期・距離の取り直しが続く |
| v0.8 登場人物と町の拡張 | 住人・世帯・仕事・外見のデータ化。12人の検証を前倒しし、16人、24人へ進む | 増えた人が固有の生活と役割を持ち、既存住人との関係から新しい展開が生まれる |
| v0.9 経験が人生と町に残る | 経験に応じた願いと習慣、成長・入居・転居、記憶と砂時計、全体の表現統一 | 同じ年月でも、誰と何を経験したかで暮らしと残された物が異なる |

各版では中心となる遊びを成立させることを優先する。装飾や小さな見た目の変更だけで版を進めない。進行不能、データ破損、操作の誤認など、その版の体験を妨げる問題は同じ版で直す。

## 行動の組合せから展開を作る

「観察する」「相談する」「誘う」「教える」「頼む」「手伝う」「作る」「見せる」「紹介する」「予定を変える」などを、条件と結果を持つ行動として用意する。各行動は目的、参加する役割、必要技能、時間、道具、場所、費用、相手の同意、成立したときの変化を持つ。住人は実行可能な行動を組み合わせ、途中の返答や状況に応じて計画を見直す。

例えば、故障した物を持つ住人が知人から修理できる人を紹介される。相手は余裕と関係から、教える、預かる、別の日にする、断ることを選ぶ。教わった人が後日ほかの人を助け、店の空いた時間に小さな修理の集まりができる場合もある。参加者や続き方は、実際の情報、技能、予定、経験から決める。これは目指す展開の例であり、毎回この結末へ誘導するイベントではない。

関心の近さだけでなく、技能の補い合い、勤務帯、世話の負担、互いへの期待も連鎖を変える。親切な依頼でも相手の時間を圧迫しうる。延期、行き違い、断ったあとの距離、別の相手への相談もその後の行動へつなぐ。

行動の種類は継続的に追加し、相手、目的、場所、道具、知識、経験との組合せを広げる。「無限の行動」を完成条件にはせず、プレイヤーが人物らしい理由を読み取り、予想外の続きに関心を持てることを確かめる。

## 公開する身体状態と、隠れた内面

[欲求・内面と行動の設計](needs-and-behavior-design.md)を追加した。現行の変動する欲求は空腹・疲労・交流不足・静けさの4軸で、性格・価値・関係・経験も一部の判断に接続している。一方、自律性不足、有能感不足、一般の気分などは仕様にあるだけで、実行中の状態にはまだない。この差を埋めることから始める。

元気・満腹・交流など、観察と操作に必要な身体状態は簡潔に公開する。自分で決めたい気持ち、上達の手応え、刺激、安心、承認、貢献、相手別の親密さ、成人の性欲は、非公開の数値や動機として持つ。気分、性格、価値、責任、技能、相手との関係を別にし、強い欲求一つだけで全行動を決めない。貢献や承認も全員共通の補充ゲージにはしない。

追加する状態ごとに、増える条件、回復する行動、同時に増える負担、相手の参加条件、実際の効果、見える動作を用意する。孤独だが人混みには疲れた住人が静かな同席を選ぶ、上達したい住人が教えを請い、後日に別の人を助ける、といった違いへつなぐ。誘いや移動だけで欲求を満たさず、実際に成立した活動と本人の受け止めから更新する。

性欲は成人の私的な動機として、恋愛感情、愛着、信頼、行為ごとの同意と分ける。未成年には性的なパラメータ・候補を持たせず、外見や成長モデルとは別の年齢条件を用いる。本人の欲求や関係の名称だけでは相手の参加を決めず、双方の意思、場所、時間、責任を確認する。断る、待つ、延期する、一人で過ごす選択を残す。隠し値は他の住民へ自動共有せず、プレイヤーにもすべての本心を数値で見せない。

この設計は人間の内面を完全に再現する理論ではない。既存研究と[追加したR18](research-notes.md#r18-動機能力機会を分ける)を参考にしたゲーム用の仮説として、状態だけを変えた比較、実際の生活経過、試遊を通じて採否を判断する。

## ネットから学び、思考ルーチンへ反映する

学習は次の三つに分けて進める。[調査資料](research-notes.md)と[行動仕様の拡張計画](character-spec.md#自律行動と登場人物の拡張計画)を対応づける。

| 層 | 取り入れる内容 | 実装への渡し方 |
|---|---|---|
| 開発時の継続調査 | 公的統計、行動科学の原著、生成エージェント研究、条件の分かる生活事例 | 出典と適用範囲を記録し、行動候補、知識の扱い、経験の更新、相互作用の仮説へ落とす |
| ゲーム内の経験学習 | 誰と何をしてどう感じたか、何を教わったか、どの条件で無理があったか | 状況別の期待、技能、好み、習慣、相手への認識を緩やかに更新し、次の選択へ反映する |
| 生成AIを使う比較実験 | 記憶の要約、長期目標や計画候補、会話の表現 | 同じ条件の既存方式と比較し、人物らしさ・展開・処理時間に改善がある用途から採否を決める |

継続調査は「資料を探す→人が置かれた条件と行動の関係を要約する→ゲーム内で変える規則を定める→比較する→採用または見直す」の順で行う。各版で重要な仮説を絞り、対象集団、根拠の種類、参照した版・確認日、実装先、検証結果を残す。性格と状況、習慣、対人応答、情報伝播に加え、約束後の実際の行動と信頼の回復、自発的な援助の研究を調査資料へ追加した。[R16、R17] 次は同じ人物・関係で予定変更と再履行、支援の余裕と負担を変えて比較する。個人の投稿やAIの回答は行動候補を考える材料とし、出現頻度や一般的な人間像の根拠へは昇格させない。

生成エージェント研究の記憶・振り返り・計画、行動候補と世界側の成立判定を分ける構成を参考にする。[R14、R15] 本作への有効性は比較実験で確かめる。初期方式はローカルの生活シミュレーションとし、生成AIを試す場合も時間・資源・移動・予約・同意・本人の知識を実行側で検査する。未知の行動は制作時の行動追加候補に回す。会話の文章だけで世界の事実を変更しない。

実行中の全住人に継続的なWeb検索やモデル再学習を必須にする構成は採らず、調査結果を検証済みの行動定義として版ごとに組み込む。ゲーム内の経験学習はローカルで継続できるようにする。生成AIの比較実験ではモデルの版、応答、遅延、費用、失敗時の代替処理も保存する。

## 増員を支える生活と実装

住人の追加では性格値のほかに生活歴、関心、技能、願い、責任、既知の人と情報を組み合わせる。既存8人の設定は残し、新しい住人が何を持ち込み、誰の行動を変えうるかを設計する。

人数を増やす際に、肖像・モデル、住まい、仕事、学校、世帯会計、人生の節目を人物IDから切り離す。関係や行動は役割と条件を参照する。開発中の版をまたぐ保存互換は維持要件から外し、現行版の保存・再開、同条件の再現、不正な保存の拒否を確認する。途中参加と転居は、その版の暮らしの仕組みとして実装する。組合せで作る外見にも人物を見分けられる配色、体格、髪型、持ち物を与える。

12人、16人の各段階で住宅、寝床、食事、仕事、交流場所と移動経路の供給を確認し、次の人口へ進むかを判断する。人数は仮の検証段階であり、容量や面白さの保証値ではない。近くの人と本人が知る関係から候補を絞り、状況が変わったときに再考する構成を検討する。描画、行動判断、関係更新の負荷を分けて測り、遠景表示を簡略化しても生活の結果を保つ。

## グラフィック・UI・音の更新

各版の行動を画面で読めるよう、表現の更新を並行する。最初は二人と工房一室で、誘い、返答、移動、共同作業、別れ、後日の変化まで制作する。この場面は行動と表現の試験場とし、参加者、予定、関係、経験を変えても成立するかを確かめる。プレイヤーが介入しない条件も試す。

- UIは町を広く見せ、住人一覧と履歴を畳めるようにする。選んだ人物の関心、今の行動、次の予定、働きかけを近くにまとめる。増員に合わせて人物の検索、関係をたどる操作、気になる人や出来事を追う機能を用意する。
- カメラは全体の観察と二人のやり取りへの接近を行き来できるようにする。現行のホイール依存を改め、Macのピンチ、トラックパッド移動、画面上の拡大・縮小、キーの代替を実装する。スクロール対象のUIと町の操作を区別し、配布版をトラックパッドだけで確認する。自動で寄る演出は切り替えられるようにする。
- 人物は空の軌跡のような線とセル塗りのあるJRPG調を目指す。まず全身の参照画像を作り、ChromeのTripoで3Dの原型を生成する。原型の顔・髪・頭身を確認してから既存のリグ・表情・動作・接触処理へ接続する。最初の1人で町の中の見え方を確かめてから他の住人へ広げる。顔、髪、衣服、共通素材を仕上げ、視線、ためらい、相づち、道具を使う手、着席・起立のつながりを優先する。既存のリグと接触処理は流用を検討する。
- 町は用途から造形する。店の陳列、工房の作りかけの物、家庭ごとの持ち物、昼夜の光、環境音と作業音をそろえる。一室で確かめた品質を全体へ広げる。
- 砂時計の層から実際の出来事、関わった人物、写真、作品、続く習慣を開けるようにする。創発した出来事の起点と続きは、必要なときに振り返れる形にする。

全住人の詳細情報を常時並べず、住人の振る舞いと配置で関係が伝わる画面を目指す。

人物制作は晴を先行し、採用した全身画像からChromeのTripoで原型を生成した。専用の骨と重み、9クリップ、3段階のLOD、元のアトラスを使うセル塗り、瞬きと睡眠時の閉眼をゲームへ接続している。[実ゲームの検証記録](verification/v0.5/haru-jrpg-gameplay/)では、12人の町で自然に選ばれた歩行、会話、共同修理、食事、睡眠と保存・再開を追う。笑顔の変形、髪の加齢、歩行時の足滑りの仕上げは別に残す。

続いて咲・智・結衣も、各人の体格と衣服へ合わせた専用のスキン、9クリップ、3LODと2つの目の制御を接続した。[3人の実町検証](verification/v0.5/jrpg-renewal-gameplay/)で、自然な会話・共同制作の完了・寝食・起床と保存再開を追った。咲と結衣には裾の補助骨を加え、手と脚が混ざって伸びる重みを直した。他の住人と成長後の凛も [共通テイストの参照画像](../assets/artwork/jrpg-resident-renewal/README.md) を用意した。新しい原型は、元画像との造形、実際のスキン変形、顔の制御、家具や相手との接触、近景・遠景の見え方を確かめてから順に採用する。人口は12人を維持し、この制作をv0.5の品質改善として進める。

**現行のTripo由来の専用モデルは4人で、残り8人は旧モデルである。** 参照画像が完成していても、住民モデルの更新済みとは数えない。生成原型、リグやLODの導入、実際の画面での見栄えはそれぞれ別に受け入れる。追加生成を行う場合もChromeで操作し、現時点で新たな有料生成は行っていない。

次の人物表現の受け入れでは、4人の元画像・原型・ゲーム内の同じ角度の近景と通常距離を並べ、頭身、顔、髪、服の輪郭、目・口、セル塗りと陰影を比較する。選択時のLOD、昼夜の明るさ、顔の白飛び、輪郭の見え方も調べる。実際の歩行では足と裾、会話では胸・首・相手への向き、作業では支える手と操作する手・活動固有の道具を確認する。現在の汎用的な掌の上下動を、修理、録音、調理、縫製などで意味の違う動きへ置き換える。4人の足接地調整は実装と支持足の実測へ進めた。旧8人の支持区間と衣服・道具の干渉は引き続き調整する。

### 行動の工程と街の物をつなぐ

[モーションと街の相互作用の設計](motion-and-world-interaction.md)を追加した。ユーザーの「見ているだけで楽しい」という要望を、クリップの種類だけでなく、道具・家具・遊具・相手を扱う一連の動作の品質として受け入れる。11月4日の実装では、同じラジオを棚から取り出して運び、二人が支える/調整する役を分け、返却する工程を接続した。四目並べには16個の実駒、盤面、手番、反応、片付け、自律的な誘いを入れた。会話の番と上体・視線、晴・咲・智・結衣の支持足も更新した。全活動・全体格の品質受け入れを完了扱いにはしない。

最初は工房一室で、棚の物を取り、台へ運び、二人が支える手と操作する手を分担して修理・制作し、確かめ、完成物を見せ、片付けて離れるところまで通す。同じ物のID、持ち主、保持先、予約、工程を世界側で持ち、手元に物を複製して見せるだけの実装にしない。中断・保存再開・倍速・距離による描画変更でも状態を保つ。

その後、作業を止めて相手を見る、話す番と聞く番、相づちと間、遊びの準備・手番・反応・片付けへ広げる。欲求や経験から選んだ行動を、人物固有の姿勢・確認・ためらい・反応へつなぐ。食事、着席・起立、寝起きも同じ工程と接触の基盤で仕上げる。

受け入れは近づく前から終了・退出まで連続して行う。接地中の足、把持点と指・手首、物の所在と重複、家具や人との干渉、実際に起きた結果を確認する。骨や目標点が動いた、静止画で道具を持った、という検査だけでは破綻の解消や見守る楽しさを証明したとしない。通常の町で自発的に起きた行動と、人が説明を閉じて観察する試遊も必要とする。

## 季節・服装・社会の変化を暮らしへつなぐ

ユーザーの追加要望を受け、[世界の条件と行動の拡張設計](world-context-and-actions.md)を追加した。環境の変化を、見た目だけでなく、身体の受け取り方、家計、知った情報、目的と予定、物と相手を扱う工程へつなぐ。

1. **気象の基盤**。現在は季節名と昼夜が中心。まず通信不要の仮定気候で晴雨・気温を再現可能に進め、屋外の休息・趣味・交流と、屋根のある代案の評価を変える。実際の道を通って移動し、日課・勤務・世話・先約と相手の同意は保つ。その後、気象庁などの資料から出典つきのデータパックへ進む。
2. **衣服を実物として扱う**。一着の上着から、取り出す、着る、脱ぐ、収納、濡れ、乾燥、洗濯と選び直しを接続する。形状、rig、LOD、袖と手・机の接触まで確認し、既存の一体meshの色変更を着替え完了とは扱わない。
3. **物価・供給と家計**。食費や部品など限られた費目から、価格、在庫、入荷待ち、見積り、修理・購入・代用品をつなぐ。同じ値上がりでも、世帯の支出、技能、愛着、予定によって対応を分ける。
4. **雇用・地域行事・世界情勢**。求人、応募と相談、開催案内、輸入部品の条件などを、本人が見聞きした情報から実際の行動へ渡す。外部の出来事だけで全員の心理や仕事を一括決定しない。

調査対象には気象庁、e-Statの物価/家計/雇用、日本銀行の企業物価と短観、自治体の開催案内、国際貿易資料を含める。公表日・対象期間・地域・単位と欠測を保持し、架空の町向けの変換と調整値は資料の事実と分ける。通常の町は保存済みパックで進み、後日の通信や訂正で過去の請求・予定・経験を変えない。初期の仮定気候を実測や予報として表示しない。

### 行動を固定の一覧で閉じない

行動の種類を6活動などの固定上限へ閉じず、**目的＋動詞＋実物/場所＋相手と役割＋状況＋工程＋個性と履歴**として定義を増やす。たとえば雨の同じ午後でも、服を乾かす、場所を借りる、修理を頼む、家計を相談する、室内へ誘い直す、雨の写真を撮りに行く、次の予定まで待つ、といった違いを本人の理由から組み立てる。

カタログは生活、身支度、仕事、制作、移動、学び、遊び、世話、地域参加などへ拡張し、道具・場所・工程を後から登録できる構造にする。候補は実行時に近くの物・既知の相手・必要な目的から絞ってMacの負荷を保つ。物や姿勢が未対応の行動を、自由文や行動名だけで成功させず、実工程・成立条件・結果と一緒に追加する。

## 比較と試遊による判断

v0.6から、保存できる初期条件と乱数seedを使った比較を行う。新規開始ごとに初期乱数を変え、初期条件と選択を再現するためのseedを保存する。開発用にはseedを指定できるようにし、現在の固定seedに加えて異なる初期関係・住人構成も試す。

最初の自動比較は同じ8人・同じ町の10seedで12代表日を進める条件を目安にする。無介入と同じ働きかけを行う条件を比べる。次に、同じseedで住人の経験、関係、勤務、設備の一つを変え、違いがどこから生まれたかを追う。人数と人生の長さに応じて比較範囲を広げる。

| 見るもの | 改善を判断する条件 |
|---|---|
| 自律性 | プレイヤーが操作しなくても、本人発の相談、交流、学習と日常が進む |
| 個性と経験 | 人物ごとの傾向を保ちながら、同じ人物でも相手・状況・経験で選択が変わる |
| 欲求と行動 | 状態を一つ変えた比較で、実行と充足・負担が変わる。競合する欲求にも対応でき、表示だけの値や一種類の行動への集中を作らない |
| 人物間の連鎖 | 紹介、教え合い、分担などが第三者の機会を変え、記録から原因をたどれる |
| 再プレイ | 台詞や時刻だけでなく、参加者、関係、習慣、作品、進路に意味のある違いが残る |
| 読み取りやすさ | プレイヤーが気になる人を覚え、行動の理由と出来事の続きについて自分の言葉で話せる |
| 私生活 | 隠れた動機を他者の全知へ変換せず、表明した意思・観察・実際の経験から関係が変わる。成人条件、双方の意思、辞退・中断を保存再開後も保つ |
| 再現と安定 | 同じ実装・行動定義の版、初期状態、seed、入力で結果を再現でき、保存と倍速でも事実が矛盾しない。生成AI利用時はモデル版を記録し、保存した応答を再生する |

行動数、会話量、交流数だけで面白さを判定しない。関心や生活条件が異なっても全員が同じ行動へ収束する、理由なく同じ人へ集まる、未知の情報が瞬時に共有される、予約待ちや断られた誘いを繰り返す、出来事が多すぎて追えない場合は設計を見直す。

初見3〜5人程度の試遊を段階ごとに行い、操作の理解、人物への関心、予想と結果の受け止めを確認する。小人数の試遊は次の設計判断の材料とし、面白さや人間らしさを一般的に実証したとは扱わない。各版の実装、比較条件、試遊で分かったことをGitHubのIssueとMilestoneへ記録し、配布物と既知の制限をReleaseに対応づける。

## 完成条件

- 町と住人が3Dで描画され、段階的に増やした人物が予定、欲求、責任、関係、本人の知識と経験から自律的に行動する。
- 働きかけには受諾、保留、辞退、別案があり、実際の移動と参加が成立した交流だけを記憶する。
- 欲求・内面の状態と行動の効果が接続し、競合する欲求、個人差、相手の意思、実際の充足と負担が次の選択を変える。公開する状態と私的な内面を分ける。
- 仕事、家庭、一人の時間、交流にそれぞれ意味があり、共通の人生点数を最大化する遊びにしない。
- 関係と経験が次の行動につながり、年月による役割や目標の変化と、残された物や習慣を見届けられる。
- 特定の人物ペアに固定しない行動と人物間の連鎖があり、住人構成や初期条件の違いから別の展開が生まれる。
- 調査資料、ゲーム用の仮説、実行される行動定義、検証結果を対応づけ、継続的に思考ルーチンを改善できる。
- メニュー、HUD、観察、場所の変更、振り返り、設定、保存、再開が一つのゲームとしてつながる。
- Macのトラックパッドだけでも、カメラの移動・拡縮・人物の選択・提案と記録の閲覧が配布アプリで行える。
- 歩行、会話、共同作業、着席、休息などを、人物と相手の状態に対応した動きで表現する。
- 作る・運ぶ・遊ぶ・話す行動が、実際の道具・家具・相手と工程ごとに接続する。物の重複や消失、空中の作業、接触の破綻を避け、中断・保存再開・倍速・距離変更でも物と行動の状態を維持する。
- JRPG調の制作資料を基準に、実際にゲームへ組み込む人物と町のモデルを仕上げる。
- Godotのシーンエディタで実際に編集し、保存されたシーンをゲームでも使用する。
- GitHubのIssue、Milestone、コミット、リリースで進捗と検証結果を追える。
- 実機での操作と複数日の進行、保存と再開、配布物の起動を確認する。

v0.1の仮モデルや簡略化した生活は途中の実装であり、完成条件の代わりにしない。
