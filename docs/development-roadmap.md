# 命の砂時計の開発計画

完成目標は、個性と生活歴の異なる住人が自律的に暮らし、出会い、協力、すれ違いから町の暮らしが変わるJRPG調3Dの人生シミュレーション。初期の8人を足場に12人、16人、24人へ段階的に増やし、住人の組合せ、経験、関係、環境によって、遊ぶたびに異なる展開が生まれるゲームとして仕上げる。

プレイヤーは気になる人を見守り、場所、予定、道具、負担の分担に働きかける。住人も自分から誘い、相談し、学び、断り、別の方法を考える。個人の選択が別の人の機会や判断を変え、その積み重ねが習慣、集まり、作品、進路、継承へつながることを面白さの中心に置く。

Godot 4.7を使用する。町、住人、家具、UI、アニメーションを保存されたシーンとリソースに分け、シーンエディタで配置や調整ができる構成にする。画像資料をゲーム画面の代わりに置かず、実際の3D空間で住人が移動して行動する。

## 現在地と今後の順序

2026年11月3日に計画を改訂した。v0.1〜v0.4で日常、関係、仕事と家庭、年月の基盤を作り、v0.5では人物・家具・町の表現を制作している。v0.6では共同活動の定義、個人の知識、状況別の経験学習、自発的な共同作業に加え、日課を避けた将来の約束と、自分から家事・世話の支援を頼む計画を接続した。画面の折り畳みと遠景人物の簡略表示も実装した。[検証と未完了の範囲](verification/v0.6/README.md)を記録する。v0.5とv0.6全体の受け入れは継続中であり、人数や試験条件は開発の目安とする。

共同制作と話題の人物IDによる分岐は活動定義へ移した。増員に合わせ、次の願い、肖像と外見、世帯・仕事・人生条件も定義から読める構成へ広げる。初期8人の生活上の固有処理は残る。[行動モデル設定案](../data/behavior-model.json)全体は実行コードに接続されていないため、資料への追記と実際の思考ルーチンの変更を区別する。

最初の10seed比較で多かった見送りに対し、食事・休息の準備、個別の移動、最大二回の再相談を接続した。当初の日時での参加と、予定変更後の参加を分けて同じseedで比較し、相談案件の完了が増えたことを確認した。実会話での紹介から後日の協力へつながる一例も、同じプレイの記録で追った。次は経験による選び方と理由の読み取りやすさ、教わった人から別の人への協力、複数人の集まりを検証する。約束や誘いの繰り返しと生活の負担も引き続き調整する。

住民同士の接点を増やすため、v0.8の人口拡張の一部を前倒しし、12人の町を先に検証する。新しい4人には、写真や模型を楽しむ午前勤務の図書館員、早番の修理補助、午後に受注作業をする縫製職、午後の音楽講師という異なる生活と技能を与える。既知の関係は少数から始め、初対面の相手の技能を町全体で共有しない。住まい、寝床、食事の席、通路を同時に用意する。

8人と12人の無介入経過では、交流の総数に加え、一人当たりの交流、相手の偏り、新旧住人の接点、仕事・食事・休息の負担を分けて見る。人数が増えても、同じ相手への集中や誘い直しだけが増える場合は、16人へ進む前に生活時間、場所、誘いの条件を調整する。v0.5〜v0.7の未完了項目は維持し、人数だけで版の完成とはしない。

| 版 | 中心となる要素 | 完了を判断する体験 |
|---|---|---|
| v0.1 日常ときっかけ | 8人の日課、移動、観察、提案と返答、利用可能な場所 | 人物を選び、その事情に合う働きかけと反応を確かめられる |
| v0.2 関係と記憶 | 方向のある関係、共同体験、約束、別案、習慣 | 同じ操作でも相手と過去の経験で結果が変わり、それを説明できる |
| v0.3 仕事と家庭 | 収入、仕事の喜び、家事や世話、支援、個人の目標 | 人柄だけでなく生活の条件によって選択が変わる |
| v0.4 年月と人生 | 加齢、転居、退職、願いの変化、継承と別れ | 時間の区切りが行動を変え、誰かの経験が町に残る |
| v0.5 人物の表現 | JRPG調モデル、相互行為のアニメーション、音と演出 | 行動、視線、姿勢から、本人と相手の様子を読み取れる |
| v0.6 個性と経験から選ぶ | 行動の部品化、本人が知る情報、短い計画、状況別の学習。まず8人で検証 | 同じ人物でも経験や状況で選択が変わり、同じ状況でも人物ごとの理由がある |
| v0.7 人と人から展開が生まれる | 住人発の誘い、紹介、教え合い、分担、約束の修復、集まり | 固定ペアの指定がなくても、第三者を介した出会いや協力が次の出来事を生む |
| v0.8 登場人物と町の拡張 | 住人・世帯・仕事・外見のデータ化。12人の検証を前倒しし、16人、24人へ進む | 増えた人が固有の生活と役割を持ち、既存住人との関係から新しい展開が生まれる |
| v0.9 経験が人生と町に残る | 経験に応じた願いと習慣、成長・入居・転居、記憶と砂時計、全体の表現統一 | 同じ年月でも、誰と何を経験したかで暮らしと残された物が異なる |
| v1.0 完成版 | 導入、一連の進行、操作設定、保存と復帰、性能、安定性、配布 | 初見で町の変化を追い、気になる人物を覚え、保存して続きを遊べる |

各版では中心となる遊びを成立させることを優先する。装飾や小さな見た目の変更だけで版を進めない。進行不能、データ破損、操作の誤認など、その版の体験を妨げる問題は同じ版で直す。

進捗は [v0.6 #12](https://github.com/hayatok/hourglass_of_life/issues/12)、[v0.7 #13](https://github.com/hayatok/hourglass_of_life/issues/13)、[v0.8 #14](https://github.com/hayatok/hourglass_of_life/issues/14)、[v0.9 #15](https://github.com/hayatok/hourglass_of_life/issues/15)と、それぞれに対応するMilestoneで管理する。v0.5の表現制作と、v0.6以降の行動の試作・検証は並行して進める。

## 行動の組合せから展開を作る

「観察する」「相談する」「誘う」「教える」「頼む」「手伝う」「作る」「見せる」「紹介する」「予定を変える」などを、条件と結果を持つ行動として用意する。各行動は目的、参加する役割、必要技能、時間、道具、場所、費用、相手の同意、成立したときの変化を持つ。住人は実行可能な行動を組み合わせ、途中の返答や状況に応じて計画を見直す。

例えば、故障した物を持つ住人が知人から修理できる人を紹介される。相手は余裕と関係から、教える、預かる、別の日にする、断ることを選ぶ。教わった人が後日ほかの人を助け、店の空いた時間に小さな修理の集まりができる場合もある。参加者や続き方は、実際の情報、技能、予定、経験から決める。これは目指す展開の例であり、毎回この結末へ誘導するイベントではない。

関心の近さだけでなく、技能の補い合い、勤務帯、世話の負担、互いへの期待も連鎖を変える。親切な依頼でも相手の時間を圧迫しうる。延期、行き違い、断ったあとの距離、別の相手への相談もその後の行動へつなぐ。

行動の種類は継続的に追加し、相手、目的、場所、道具、知識、経験との組合せを広げる。「無限の行動」を完成条件にはせず、プレイヤーが人物らしい理由を読み取り、予想外の続きに関心を持てることを確かめる。

## ネットから学び、思考ルーチンへ反映する

学習は次の三つに分けて進める。[調査資料](research-notes.md)と[行動仕様の拡張計画](character-spec.md#自律行動と登場人物の拡張計画)を対応づける。

| 層 | 取り入れる内容 | 実装への渡し方 |
|---|---|---|
| 開発時の継続調査 | 公的統計、行動科学の原著、生成エージェント研究、条件の分かる生活事例 | 出典と適用範囲を記録し、行動候補、知識の扱い、経験の更新、相互作用の仮説へ落とす |
| ゲーム内の経験学習 | 誰と何をしてどう感じたか、何を教わったか、どの条件で無理があったか | 状況別の期待、技能、好み、習慣、相手への認識を緩やかに更新し、次の選択へ反映する |
| 生成AIを使う比較実験 | 記憶の要約、長期目標や計画候補、会話の表現 | 同じ条件の既存方式と比較し、人物らしさ・展開・処理時間に改善がある用途から採否を決める |

継続調査は「資料を探す→人が置かれた条件と行動の関係を要約する→ゲーム内で変える規則を定める→比較する→採用または見直す」の順で行う。各版で重要な仮説を絞り、対象集団、根拠の種類、参照した版・確認日、実装先、検証結果を残す。性格と状況、習慣、対人応答、情報伝播に加え、約束後の実際の行動と信頼の回復、自発的な援助の研究を調査資料へ追加した。[R16、R17] 次は同じ人物・関係で予定変更と再履行、支援の余裕と負担を変えて比較する。個人の投稿やAIの回答は行動候補を考える材料とし、出現頻度や一般的な人間像の根拠へは昇格させない。

生成エージェント研究の記憶・振り返り・計画、行動候補と世界側の成立判定を分ける構成を参考にする。[R14、R15] 本作への有効性は比較実験で確かめる。初期方式はローカルの生活シミュレーションとし、生成AIを試す場合も時間・資源・移動・予約・同意・本人の知識を実行側で検査する。未知の行動は制作時の行動追加候補に回す。会話の文章だけで世界の事実を変更しない。

実行中の全住人に継続的なWeb検索やモデル再学習を必須にする構成は採らず、調査結果を検証済みの行動定義として版ごとに組み込む。ゲーム内の経験学習はローカルで継続できるようにする。生成AIの比較実験ではモデルの版、応答、遅延、費用、失敗時の代替処理も保存する。

## 増員を支える生活と実装

住人の追加では性格値のほかに生活歴、関心、技能、願い、責任、既知の人と情報を組み合わせる。既存8人の設定は残し、新しい住人が何を持ち込み、誰の行動を変えうるかを設計する。

人数を増やす際に、肖像・モデル、住まい、仕事、学校、世帯会計、人生の節目を人物IDから切り離す。関係や行動は役割と条件を参照する。開発中の版をまたぐ保存互換は維持要件から外し、現行版の保存・再開、同条件の再現、不正な保存の拒否を確認する。途中参加と転居は、その版の暮らしの仕組みとして実装する。組合せで作る外見にも人物を見分けられる配色、体格、髪型、持ち物を与える。

12人、16人の各段階で住宅、寝床、食事、仕事、交流場所と移動経路の供給を確認し、次の人口へ進むかを判断する。人数は仮の検証段階であり、容量や面白さの保証値ではない。近くの人と本人が知る関係から候補を絞り、状況が変わったときに再考する構成を検討する。描画、行動判断、関係更新の負荷を分けて測り、遠景表示を簡略化しても生活の結果を保つ。

## グラフィック・UI・音の更新

各版の行動を画面で読めるよう、表現の更新を並行する。最初は二人と工房一室で、誘い、返答、移動、共同作業、別れ、後日の変化まで制作する。この場面は行動と表現の試験場とし、参加者、予定、関係、経験を変えても成立するかを確かめる。プレイヤーが介入しない条件も試す。

- UIは町を広く見せ、住人一覧と履歴を畳めるようにする。選んだ人物の関心、今の行動、次の予定、働きかけを近くにまとめる。増員に合わせて人物の検索、関係をたどる操作、気になる人や出来事を追う機能を用意する。
- カメラは全体の観察と二人のやり取りへの接近を行き来できるようにする。自動で寄る演出は切り替えられるようにする。
- 人物は空の軌跡のような線とセル塗りのあるJRPG調を目指す。まず全身の参照画像を作り、ChromeのTripoで3Dの原型を生成する。原型の顔・髪・頭身を確認してから既存のリグ・表情・動作・接触処理へ接続する。最初の1人で町の中の見え方を確かめてから他の住人へ広げる。顔、髪、衣服、共通素材を仕上げ、視線、ためらい、相づち、道具を使う手、着席・起立のつながりを優先する。既存のリグと接触処理は流用を検討する。
- 町は用途から造形する。店の陳列、工房の作りかけの物、家庭ごとの持ち物、昼夜の光、環境音と作業音をそろえる。一室で確かめた品質を全体へ広げる。
- 砂時計の層から実際の出来事、関わった人物、写真、作品、続く習慣を開けるようにする。創発した出来事の起点と続きは、必要なときに振り返れる形にする。

全住人の詳細情報を常時並べず、住人の振る舞いと配置で関係が伝わる画面を目指す。

## 比較と試遊による判断

v0.6から、保存できる初期条件と乱数seedを使った比較を行う。新規開始ごとに初期乱数を変え、初期条件と選択を再現するためのseedを保存する。開発用にはseedを指定できるようにし、現在の固定seedに加えて異なる初期関係・住人構成も試す。

最初の自動比較は同じ8人・同じ町の10seedで12代表日を進める条件を目安にする。無介入と同じ働きかけを行う条件を比べる。次に、同じseedで住人の経験、関係、勤務、設備の一つを変え、違いがどこから生まれたかを追う。人数と人生の長さに応じて比較範囲を広げる。

| 見るもの | 改善を判断する条件 |
|---|---|
| 自律性 | プレイヤーが操作しなくても、本人発の相談、交流、学習と日常が進む |
| 個性と経験 | 人物ごとの傾向を保ちながら、同じ人物でも相手・状況・経験で選択が変わる |
| 人物間の連鎖 | 紹介、教え合い、分担などが第三者の機会を変え、記録から原因をたどれる |
| 再プレイ | 台詞や時刻だけでなく、参加者、関係、習慣、作品、進路に意味のある違いが残る |
| 読み取りやすさ | プレイヤーが気になる人を覚え、行動の理由と出来事の続きについて自分の言葉で話せる |
| 再現と安定 | 同じ実装・行動定義の版、初期状態、seed、入力で結果を再現でき、保存と倍速でも事実が矛盾しない。生成AI利用時はモデル版を記録し、保存した応答を再生する |

行動数、会話量、交流数だけで面白さを判定しない。関心や生活条件が異なっても全員が同じ行動へ収束する、理由なく同じ人へ集まる、未知の情報が瞬時に共有される、予約待ちや断られた誘いを繰り返す、出来事が多すぎて追えない場合は設計を見直す。

初見3〜5人程度の試遊を段階ごとに行い、操作の理解、人物への関心、予想と結果の受け止めを確認する。小人数の試遊は次の設計判断の材料とし、面白さや人間らしさを一般的に実証したとは扱わない。各版の実装、比較条件、試遊で分かったことをGitHubのIssueとMilestoneへ記録し、配布物と既知の制限をReleaseに対応づける。

## 完成条件

- 町と住人が3Dで描画され、段階的に増やした人物が予定、欲求、責任、関係、本人の知識と経験から自律的に行動する。
- 働きかけには受諾、保留、辞退、別案があり、実際の移動と参加が成立した交流だけを記憶する。
- 仕事、家庭、一人の時間、交流にそれぞれ意味があり、共通の人生点数を最大化する遊びにしない。
- 関係と経験が次の行動につながり、年月による役割や目標の変化と、残された物や習慣を見届けられる。
- 特定の人物ペアに固定しない行動と人物間の連鎖があり、住人構成や初期条件の違いから別の展開が生まれる。
- 調査資料、ゲーム用の仮説、実行される行動定義、検証結果を対応づけ、継続的に思考ルーチンを改善できる。
- メニュー、HUD、観察、場所の変更、振り返り、設定、保存、再開が一つのゲームとしてつながる。
- 歩行、会話、共同作業、着席、休息などを、人物と相手の状態に対応した動きで表現する。
- JRPG調の制作資料を基準に、実際にゲームへ組み込む人物と町のモデルを仕上げる。
- Godotのシーンエディタで実際に編集し、保存されたシーンをゲームでも使用する。
- GitHubのIssue、Milestone、コミット、リリースで進捗と検証結果を追える。
- 実機での操作と複数日の進行、保存と再開、配布物の起動を確認する。

v0.1の仮モデルや簡略化した生活は途中の実装であり、完成条件の代わりにしない。
