# 季節と社会の変化から暮らしを広げる設計

2026年11月4日。季節、服装、天候、物価、雇用、地域の出来事や世界情勢を、住人の選択と実際の生活へつなぐ設計。最初の段階A0として、仮定の晴雨・気温が自由時間の候補評価と町の表示へ影響する仕組みを実装した。公式資料パック、着替え、経済・ニュースの連携、行動の合成は今後の計画である。公的資料が示す事実と、架空の町で試す因果関係を分けて記す。

## 現在の実装

現行の暦は一季節3代表日、一年12代表日である。`simulation.gd` の `calendar_text()` が季節名を表示し、生活週は7日で続く。`work_family.gd` は生活費と3日ごとの固定住居費を扱う。`season_housing` という名前の費目も、現状は気温や燃料価格から計算していない。町には昼夜の照明変化があり、今回の天候実装では雨天に応じて空・日光・環境光も変わる。

現在動いている欲求は空腹、疲労、つながり、静けさである。天候による屋外活動の負担は候補の採点へ加えたが、身体の温熱・濡れ・清潔という欲求や衣服の在庫は追加していない。気象に応じた需要、外部統計からの価格・求人の更新も未実装である。既存モデルの配色変更や人物ごとの服の違いは、衣服を選んで着替える行動には数えない。

追加設計は[欲求と行動](needs-and-behavior-design.md)、[人物の知識と経験](character-spec.md)、[モーションと街の物](motion-and-world-interaction.md)に従う。ラジオや盤のように、行動の工程と物の所在は世界側で管理する。今回の天候開発版はschema 8のみを受け入れ、天候とその乱数状態も保存する。天候導入前に配布した0955-motion版のschema 7とは区別する。後続の保存項目を実装するときも、その時点の形式で保存・再開と不正データの拒否を確認する。開発中の旧形式の互換を追加要件にはしない。

### A0で実装した天候と候補評価

`world_weather.gd` と `data/weather.json` が通信なしで晴れ・雨・気温を進める。季節別の気温や降雨の係数は架空の温帯町を想定した仮定値であり、実測値・予報・実在地域の再現ではない。天候専用の乱数と切替時刻を保存し、HUDや照明の更新では天候も住人の判断用乱数も進めない。

`resident_weather.gd` は自由時間の休息、食事、交流、趣味、写真、遺された記録を見る行動（`rest`、`eat`、`social`、`hobby`、`photo`、`legacy`）の6種類に、雨と暑さ・寒さによる有限の追加負担を与える。屋外を禁止したり、全員へ同じ行動を指示したりはしない。勤務・日課・先約と、切迫した空腹・疲労の優先順位は変えていない。共同制作や盤遊びの相談・実行を天候で変更する処理も、この段階には含めない。

屋内外は実際の活動スポットや対象座標と、保存シーンの室内範囲から判定する。同じ室内にいる場合を除き、移動負担は目的地までの直線距離を使った見積りであり、経路の屋外区間を積算した値ではない。選択後は家具を避けつつ、従来の道路と室内通路を通る経路で実際に移動する。町外の住居・学校・職場（`off_map_*`）は環境を再現していないため、屋内外不明として天候評価から外す。

A0では、一つの町に共通する現在の雨と気温を全住人が知覚できると仮定する。評価には本人の特性を使い、未来の天候や他人の家計・身体状態を直接読まない。天候を知った時刻や経路を人物ごとの知識へ保存する処理は、まだ追加していない。

時計の近くに晴雨・気温を表示し、同じ天候状態から町の空と照明を変える。雨粒、身体や衣服の濡れ、着替えは未実装である。[A0の検証記録](verification/weather-20261104/README.md)では条件をそろえた晴雨の自動比較、実経路での到着、保存再開、HUDと照明の描画を区別して記録する。新しい天候版を梱包したmacOSアプリの動作は未確認であり、人間による試遊や面白さの実証としては扱わない。

## オフライン用パックとlive取得

A0は同梱の仮定気候を使う。次のA1では通常の新規開始に制作時に選んだ公式資料から作るオフライン用データパックを使う案とする。元の資料、町へ変換した値、変換規則を同梱し、通信しなくても季節と暮らしが進む。実在地域の名称や数値を使う部分と、架空の町向けに調整した部分を表示上も区別する。

live取得は別の取り込み処理とする。取得したデータを検査して新しいパック候補にし、新規の町や選択した区切りから適用する。開いている保存データの過去や予定を、通信結果で書き換えない。取得失敗、欠測、訂正、統計の基準変更があれば、保持中のパックを使い続ける。欠測を雨量0、所得0、求人0に変換しない。

住人ごとの毎フレームWeb検索は行わない。気象、月次統計、四半期統計、随時の地域案内は、元資料の周期に応じて取り込み側で更新する。RSSの見出しは更新の発見に使い、開催条件や中止は個別案内で確かめる。

### 代表日への対応

現実の暦、資料の対象期間、公表日、ゲームで条件が変わる時刻を別に持つ。気象は同じ地域の連続した時間経過を選び、雨の開始、外出、乾燥までを一日の生活時計へ対応づける。公表前の経済情報や、予報として提供していない未来の雨を住人へ知らせない。

一年12代表日の圧縮へ、現実の月次増減をそのまま毎分適用しない。初期案では経済条件を季節の区切りで更新し、その区切りまでに公表された資料を選ぶ。採用月、集約方法、ゲームの日付との対応はパックに固定する。生活費、収入、仕入れ、固定住居費のどこを変えるかも定め、同じ値上がりを複数の費目で重複して加算しない。月と代表日の対応や係数は、現実から得た法則ではなく調整対象である。

### 再現と保存

A0では天候の経過位置・切替予定・乱数状態と、仮定気候の識別子・バージョンを保存する。次の表に公式資料・衣服・経済などを追加する際の保存項目案を示す。表全体を実装済みとはしない。識別用のハッシュを残す場合も、実際の暮らし、状態の復元、描画の検査の代わりにはしない。

| 保存する区分 | 内容 |
|---|---|
| 資料の写し | source ID、URL、対象地域・期間、公表・取得・訂正日時、元データ、欠測・品質、出典と利用条件 |
| 町への変換 | pack IDとバージョン、実在/架空の区別、暦の対応、正規化・補間・価格への反映方法、調整幅、規則と行動定義のバージョン |
| 進行中の町 | 気象の経過位置、屋内外の環境、物価・在庫・求人・配送、予約・約束、適用済みの出来事と効果、環境用乱数の状態 |
| 人物と物 | 知った案内と経路・時刻、個人の期待や経験、衣服のID・装備・保管先・濡れ・汚れ、洗濯・乾燥・着替えの工程 |

保存再開で通信や再抽選を行わず、同じ資料と条件を復元する。修正版パックを入れても過去の請求、求人、行事を再適用しない。外部由来の出来事にも一意なIDと適用済み記録を持たせる。環境の乱数を住人の判断用乱数と分け、表示する雨粒や通信の成否で人生の選択が変わらないようにする。

## 町の条件と本人が知ること

A0の現在天候に関する共通知覚を、将来の予報や経済・地域情報には広げない。後続の実装では環境の事実と、その人が知ったことを分ける。外を歩いて雨に気づく、店頭の値札を見る、掲示の求人を読む、知人から行事を聞く、といった接触を既存の知識・伝聞の流れへ接続する。住人が知るのは自分の持ち金・衣服・予定と、実際に見聞きした情報である。他人の濡れ具合、家計、雇用不安を町の共通データから直接読まない。

同じ雨でも、写真を撮りたい人、濡れたくない人、勤務へ向かう人で候補が変わる。条件は「屋外を禁止する」だけでなく、準備の時間、必要な道具、使う手、移動の負担、屋根のある代案、予定変更の相談へ渡す。約束相手は自動で同じ判断をせず、本人の余裕と知識から返答する。

仕入れと家計の両方に価格の変化を反映する。店は在庫や利益を考えて値付けし、住人は購入、見送り、修理、代用品、借用、共同購入を比較する。全国の物価指数を町の全商品の価格として扱わず、CPIを使う生活費の調整と、企業物価を使う材料費の調整を分ける。

雇用は求人の発生、情報への接触、応募、話し合い、合意した勤務の変更を経て更新する。家族の世話や先約への影響も確認する。世界情勢による供給変化も、実際に該当する取引先や品目に限って伝える。ニュースを読んだだけで全住民の気分や経済状態を一斉に同じ値へ変えない。

## 衣服と環境の物理的な要件

以下は未実装の衣服を追加する際の要件である。

着替えには別の形状を持つ衣服と、脱いだ後の身体・下の服を用意する。既存アトラスの色を変えただけでは上着を着たことや雨具を使ったことにはしない。季節用モデル、重ね着できる衣服、帽子・靴などのうち、最初に扱う範囲を決めて制作する。

衣服にはID、所有者、着用者、保管先、予約、形状と体格への適合を持たせる。温かさ、通気、雨の通しにくさ、濡れ、汚れ、乾燥・洗濯の必要をゲーム用の状態として扱う。屋内外、屋根、風、日照、暖房や乾燥場所の違いを反映し、季節名だけで全員へ一律の着替えを命令しない。

着替える、脱ぐ、干す、取り込む、畳む、しまう行動は、実在する収納・衣服・場所を使う。濡れた上着を干したら着用から外れ、乾くまでは別の選択が必要になる。洗濯中や他人が借りている服を同時に使わず、必要な時間と設備、家事の負担を残す。衣服が足りないときも、休む、屋根のある所へ移る、別の活動へ替える選択を用意する。

温熱の感じ方と行動への影響はゲーム用の仮説とする。医療上の危険や人体の正確な体温を再現するモデルとしては扱わない。費用や好み、慣れ、身支度にかけたい時間にも個人差を持たせる。

袖、裾、帽子、長い髪と、手・足・椅子・寝具・道具の接触を確認する。傘で片手を使えば、両手運搬のラジオを同時には運べない。置く、手伝いを頼む、準備を変える、待つ工程を必要とする。実際の着脱途中、着席、深い膝曲げ、運搬、睡眠、LOD切替を確認し、色の差や静止画だけで衣替えの品質を受け入れない。布の全面的な物理シミュレーションを前提にはせず、衣服ごとのスキンと動作でも接触を成立させる。

## 行動の組合せと拡張

以下の合成カタログは今後の設計である。既存の共同制作・会話・盤遊びの工程は、そのまま任意の行動を生成できる仕組みにはなっていない。

行動カタログは追加できる動詞・対象の機能・工程・成立条件の定義として持つ。「雨の日の晴専用イベント」のような人物ID別の固定台本へ閉じず、道具、相手、目的、状況、技能、個性、本人の履歴から計画を組み立てる。

| 合成する要素 | 判断に使う内容 |
|---|---|
| 目的 | 暖かく過ごす、予定を守る、壊れた物を使えるようにする、作品を見せる、相手を助けるなど。複数の目的は競合もする |
| 対象と道具 | その物で何ができるか、状態、所在、持ち主、空いた手、必要な設備、代わりに使える物 |
| 相手と役割 | 誰を知っているか、誘いと返答、教える・支える・運ぶ役、人数、互いの責任 |
| 状況 | 気象、屋根、混雑、開店時間、材料、価格、求人、行事、残り時間、知られている変更情報 |
| 工程 | 準備、移動、接触、使用、確認、結果、片付け。待つ・中断する・別案へ移る経路も持つ |
| 個人差と履歴 | 関心、技能、得意でない条件、好み、以前の相手の返答、成功・負担、習慣、最近の繰り返し |

たとえば「濡れた上着を乾かしたい」という目的から、空いた物干しへ運ぶ、場所を空けてもらう、別の乾燥場所を借りる、先に別の服を探す、といった計画を作る。誰の服か、どこが空いているか、相手に余裕があるかで工程が変わる。低い価格だけを理由に毎回同じ品を買うのでなく、修理技能、愛着、使う予定、手持ちの材料も判断へ含める。

実行時の候補数は制限して処理負荷を抑える。目的と近くの物・既知の相手から絞り、条件が変わったときに計画を見直す。ただし、行動の種類を最初の固定一覧で完結したものとせず、新しい道具、場所、技能、工程、地域の題材を追加できるようにする。

未定義の動詞や、使える実物・動作がない計画は、自由文で成功させず制作時の追加候補へ回す。会話の言い換え、乱数による細かな動き、同じループへの名前追加だけを、多様な暮らしの成立とは数えない。最終的に参加条件、時間、場所、資源、同意、本人の知識を世界側で検査し、結果を一度だけ適用する。

## 最初の実装と比較

A0の仮定気候と自由時間の評価を出発点に、A1で公式資料パックと気象を踏まえた準備・相談へ進み、Bで一着の上着を追加する案とする。衣服の段階では既存の制作机と工房を使い、上着と保管・乾燥場所を実物として追加する。確認する二人は制作上の対象であり、行動規則をその人物に固定しない。全12人分の服を先に量産する前に、準備から片付けまでを通す。

| 段階 | 実装状況と範囲 | 比較で確かめること |
|---|---|---|
| A0 仮定気候と自由時間 | 実装済み。通信不要の晴雨・気温、自由時間の6種類への追加負担、HUDと空・照明の変化、schema 8の保存 | 同じ状態から晴雨だけを変えた自動比較、実経路、保存再開、描画を確認。梱包した天候版アプリと人間の試遊は未確認 |
| A1 公式資料と気象を踏まえた計画 | 未実装。出典つきの晴天・降雨のオフラインパック。観察した雨、屋外の準備負担、屋根のある代案、誘い直し・延期を候補へ接続 | 人物・関係・予定・seedをそろえ、天候だけで準備・移動・実参加が変わる。雨でも全員が同じ選択へ収束しない |
| B 一着の衣服 | 未実装。実形状の上着、収納、着脱、濡れ、乾燥、別の服や屋内活動への選択。保存する衣服と工程を追加 | 取り出した同じ上着が着用・乾燥・収納へ移る。濡れた服の重複利用や、袖・手・道具の貫通を起こさない |
| C 家計と供給 | 未実装。食費・材料費の限られた費目、在庫と入荷待ち、見積り、修理・購入・代用品の候補 | 同じ価格変化でも世帯・在庫・技能により対応が分かれる。支出を二重計上せず、注文だけで物や技能を増やさない |
| D 仕事と出来事 | 未実装。求人の掲示と応募、架空の地域行事、該当品目の供給変化。情報の伝わり方を接続 | 知った人と知らない人が区別され、実際の合意・勤務・準備・参加から暮らしが変わる |

各段階で、途中保存、読み込み、停止、倍速、画面外の進行、参加者の退出を確認する。状態の比較、実ゲームの連続した動き、人が説明を閉じて観察する試遊を分けて記録する。候補数や行動名が増えただけでは完了とせず、住人が何を選び、何を準備し、誰が応じ、何が残ったかを見て判断する。
