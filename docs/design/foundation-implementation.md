# 基盤再構築の実装契約

## 空間

`data/foundation/ogawa-home.json` を一戸の家の正本とする。家屋、部屋、壁、扉、家具、利用点、持ち主、立入範囲を分ける。平面はx/z、長さはm、床はy0とする。図面と実3Dの両方をこの定義から作り、別々の見た目と判定を手で同期しない。

- 部屋は壁を除いた内法のboundsを持つ。
- 壁は中心線、厚み、高さを持つ。扉は壁IDと開口幅を持ち、実際に壁へ穴を開ける。
- 家具は占有boxと利用点・向き・利用可能な行動を持つ。利用点に行けなければ実行を開始しない。
- 部屋と扉のgraphが立入と到達を決め、閉扉・占有・通行不可は実行結果として返す。経路が失敗した時の壁抜け直線は返さない。
- 床上の通行と家具/壁の衝突、設備の予約、扉の状態と居室の公開範囲は同じ状態から表示する。
- 人が歩いて近づく `interaction_point` と、着座・横臥時の身体の許可領域 `usage_region` を分ける。物を置く面は `support_point` と実収納先 `support_fixture`、置ける種類は `put_down_kinds` で定義する。棚の高さから架空の作業台を作らない。

## 住民の身体

`ResidentMotor` は身体の唯一の位置・速度・向き・経路を持ち、実秒とmで連続的に移動する。Simの一分ごとの位置の段差と、見た目だけの指数補間の組合せは継続しない。

歩行素材とAnimationTreeは、このmotorの実速度・加減速・旋回・接地位相へ接続する。出発/停止/方向転換/着座/起立のつながりを全身の動作で作る。モデル間の転用は骨名だけでなくrest pose・体格・衣服を確認する。motorの数値テストだけでは自然な歩容の完了としない。

家具への出入りもmotorが連続した世界位置を持つ。椅子を引く・横を回る・座る・寄せる・使用する・立つ・椅子を戻すを一つの予約内で行い、動かした椅子は絵・実接触形状・経路の障害物を一緒に更新する。寝床では端に座り、脚を入れ、胴体を横たえ、逆順に出る。全身poseと実座面・寝具・床の接触を確認してから実使用を許す。

## 生活を実行する

行動の意図と動作を分け、実行系が設備予約・接近・向き合わせ・使用・物の受渡し・片付け・退出を管理する。食事は調理済みの実物を食べてから回復し、衛生は実際に利用した設備と時間から更新する。占有待ち・辞退・急な予定変更は、物と設備を安全に解放して残る工程を保存する。

世帯は財布だけでなく、食材・料理・食器・衣類・家事の依頼・子の世話と担当を持つ。担当は人物IDの特例ではなく、その人の予定・技能・関係・経験・意思から選ぶ。

`arrive → entering → begin_use → perform → begin_exit → end_use → finish` を家具の使用契約とする。enter/exit時間を実作業へ加算しない。中断の意思が生じても物と設備を先に解放せず、安全な退出を終えてから中断を確定する。保存は意図、工程、身体・全身pose、物の所在、家具の移動、占有を一緒に検証する。復元した姿勢を実際に再描画するまでは生活時計を進めない。

## 段階1を閉じる条件

[最初の実装設計](life-foundation.md)の24時間、動作、競合、事情への適応、保存再開を実ゲームで確認し、Macアプリをビルドする。図面、構造データ、設計確認用3D、単体試験は途中の成果であり、この段階の完成を表さない。

## 歩容素材の調達

歩行素材は自作FKの振幅を小さくして高速再生する方式から置き換える。候補の [Quaternius Universal Animation Library](https://quaternius.com/packs/universalanimationlibrary.html) は公式にCC0、Godot用GLB、root motion版とその無効版を提供する。無料Standardの実収録内容・ライセンスを確認して原本と出典を保存し、基準rigで比較する。素材の取得は、リターゲットや自然な歩行の完了には数えない。
