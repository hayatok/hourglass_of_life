# 欲求・内面と行動を一緒に広げる設計

2026年11月3日。短い実プレイから「人物のパラメータと行動が薄い」という指摘を受けた改訂案。**この文書の新しい状態・行動は未実装**。現在の実装と分け、[ロードマップ](development-roadmap.md)のv0.6〜v0.9へ組み込む。

目指すのは、暮らしの条件と内面が変わることで、同じ住民の選択と、その相手の次の行動まで変わること。隠しパラメータは持つが、プレイヤーは数値の正解探しだけでなく、振る舞い、返答、繰り返す習慣から人物を知れるようにする。

## 現在動いているものと、足りないもの

| 層 | 現行の実装 | 次に接続するもの |
|---|---|---|
| 変動する欲求 | `hunger`、`fatigue`、`connection`、`quiet`。時間と食事・休息・交流などで更新 | 自律性、有能感、刺激、安全・安心、成人の親密な動機などと、それぞれを変える行動 |
| 性格と価値 | 5性格軸の定義があり、現在は4軸を判断に使用。価値6軸も使用 | 未接続の否定的情動性、状況への反応の強さ、経験から緩やかに変わる価値・習慣 |
| 気分 | 仕事の手応えはあるが、一般の快・不快、活発さ、緊張はない | 直近の出来事の受け止めと回復。恒常的な性格と区別 |
| 関係と経験 | 方向付きの親しさ・信頼・気楽さ・期待、本人の知識、技能、状況別の経験 | 愛着、恋愛的な関心、守りたい距離、行き違いと修復。方向性と個別の履歴を維持 |
| 選択の設定 | 実コードに採点や更新処理がある | 欲求・効果・実行条件を共通の定義へ移す。`behavior-model.json`の設計値が全部動いているとは扱わない |

主な接続先は `simulation.gd` の欲求更新・候補選択、`resident_cognition.gd` の経験、`resident_planner.gd` の計画、`resident_activities.gd` の活動、`social_life.gd` / `resident_agenda.gd` / `work_family.gd` の相談・参加条件である。

## 状態を分ける

短時間で上下する欲求と、性格、価値観、技能、相手との関係、責任を別に持つ。たとえば「孤独だが人混みは疲れる」「近づきたいが、約束した仕事も大切」「認められたいが作品には自信がない」が同時に存在できるようにする。

欲求の不足は原則0〜1で、1ほど満たされていない状態。性欲などの動機の強さは0〜1でも、不足や不幸と同じ意味にしない。気分の快・不快は符号を持つ別の状態とする。すべてを毎時間増えるゲージへ変換しない。

| 欲求・動機の候補 | プレイヤーへの表示 | 高まりやすい条件のゲーム用仮説 | 満たす行動と、同時に起こりうる負担 |
|---|---|---|---|
| 空腹、疲労 | 満腹、元気として公開 | 食事からの経過、活動、睡眠不足 | 食べる、休む、眠る。時間・食費を使う |
| つながり | 現在の交流ゲージは維持。相手別の細部は隠す | 意味のある交流がない、話したかった相手と会えない | 近況を話す、誘う、便りを送る。交流で疲れる場合もある |
| 静けさ、刺激から離れたい気持ち | 直接の数値は隠し、本人の返答や姿勢で示す | 長い接客、騒がしい集まり、連続する依頼 | 一人で読む、静かな散歩、親しい人と別々に作業。交流不足は残りうる |
| 自分で決めたい気持ち | 隠す | 引き受けた負担や指示が続き、自分の時間を取れない | 自分で予定を立てる、断る、別案を出す。制作や約束を先送りする場合もある |
| 上達・達成の手応え | 欲求値は隠す。習得・作品・進捗は見せる | 難しい作業で停滞、自分の力を試す機会がない | 練習する、教わる、分担して完成する。疲労や失敗もありうる |
| 新しさ・好奇心 | 隠す | 慣れた行動ばかり、本人が関心を持つ未知の機会を知る | 新しい場所へ行く、試作、初めての相手に教わる。移動や緊張が増える |
| 安全・安心を確かめたい気持ち | 不安の正確な値は隠す。原因となる出来事は分かる範囲で示す | 実際の予定変更、生活費への懸念、失敗や行き違い | 予定を確認する、相談する、修理・備え、落ち着ける場所で過ごす。確認の繰り返しには歯止めを置く |
| 認められたい気持ち | 隠す | 本人が大事にした努力を共有できない、期待した応答がない | 作品を見せる、発表する、助言を求める。評価への緊張や落胆もありうる |
| 貢献・世話をしたい動機 | 隠す。行動と引き受けた責任は見せる | 相手の困り事を知り、本人の価値や経験と結びつく | 手伝う、教える、差し入れる。自分の余裕を使い、相手が望まない場合は成立しない |
| 特定の相手と親しく過ごしたい気持ち | 隠す。表明した関心や成立した関係は記録 | 共有体験、会いたい相手との距離、本人の受け止め | 二人で散歩、気持ちを話す、デートへ誘う。相手の思いとは独立し、保留や辞退もある |
| 成人の性欲 | 非公開 | 個人差、疲労・ストレス、関係や状況に応じて変化する設計 | 成人同士で双方が望む親密な時間、誘いの延期や一人の時間の選択。露骨な描写は前提にしない |
| 水分、清潔、身体の快適さ | 後続候補。必要なものだけ簡潔に公開 | 暑さ、作業、設備や生活条件 | 飲む、身支度、入浴、快適な場所へ移る。施設と生活時間を用意してから導入 |

上表は研究から得た普遍的な欲求一覧や係数ではなく、本作で試す設計候補。貢献や承認を全員共通の欠乏ゲージにせず、価値観・関係・機会に反応する動機として扱う。水分や清潔を増やす場合も、毎日同じ補充作業へ偏らないか確かめる。

長期の個人差には、基準となる強さ、消耗・回復への感受性、刺激の好み、距離の好み、断り方、経験した成功・負担を使う。一回の経験で性格を反転させず、性別や見た目から親密さや世話への意欲を決めない。関心の弱い人物にも通常の生活が成立し、恋愛や性的な活動の不成立だけで罰や進行不能を作らない。

喜び、落胆、怒り、不安、気まずさ、嫉妬などは、起点の出来事、向けられる相手、本人の解釈、強さ、和らぐ条件を持つ短期の感情として候補にする。たとえば行き違いを知って不安になった人が、問い詰めるだけでなく、確かめる、時間を置く、相談することを選べるようにする。事実、伝聞、誤解を区別し、出来事のない怒りや嫉妬を全員に定期発生させない。

## 成人の私的な動機と、相手の意思

性欲、恋愛感情、愛着、親しさ、相手への信頼、行為ごとの同意を別の状態として定義する。本人の欲求が強いことや、恋人・同居人であることだけでは、相手の参加を成立させない。

性的な状態と行動候補はゲーム上18歳以上にのみ用意する。未成年には該当するキー自体を生成しない。年齢判定を外見から分離し、現在の凛の12歳からの成長モデルへの切替を成人判定には使わない。保存・読み込み・加齢・転居でも同じ条件を守る。

相手を伴う私的な活動は、年齢、本人が知る関係、双方のその時点の意思、場所の私的性、時間と責任を満たしてから予約・移動・開始する。途中でも各人がやめられる。辞退後に同じ条件で誘い続けず、待つ、別の過ごし方を選ぶ、別日に相談する余地を残す。内面の隠し値を他人の知識や町のうわさへ自動転記しない。

## 行動によって状態を変える

欲求の定義には、ID、意味、対象年齢、表示方法、自然変化、起点となる出来事、充足上限、個人差を持たせる。行動側には、誰のどの状態をいつ変えるかを定義する。

- 時間による自然変化、実際の行動時間による効果、完了・中断などの一度だけの効果を分ける。入力のたび、描画フレームのたびには適用しない。
- 誘いを送った、約束した、向かい始めただけでは、交流や親密な時間が成立した効果を与えない。
- 一つの行動が複数の状態を変える。共同制作で達成感とつながりを得ても、疲労や静けさへの欲求が増えることがある。参加者ごとに受け止めと効果を計算する。
- 期待した効果と実際の結果を分ける。慣れ、飽き、場所、相手、最近の経験によって見込みを更新し、毎回同じ量だけ回復する最適行動を固定しない。
- 中断時は実際に過ごした時間と成立した事実だけを残す。完了イベントの二重適用を防ぎ、場所・材料・予定を解放する。

更新の形は「現在値＋生活時間に応じた変化＋成立した出来事の効果＋実行時間に応じた効果」。係数はゲーム用の仮設定として比較する。気分は出来事の解釈と休養から短期に変え、技能・習慣・価値の更新速度と分ける。

実装時は欲求の管理を専用モジュールとデータへまとめ、既存4欲求を先に移す。新しい状態のID・範囲・対象年齢・更新済みイベントと個人差を現行形式の保存検証へ加える。候補は本人が知る相手と近隣の機会から絞り、毎描画フレームに全人物・全行動を総当たりしない。新しい方式への移行時に、旧版の採点設定が読み込まれていない状態も解消する。

## 思考ルーチンへの接続

1. 本人の欲求・感情・目標と、本人が知る相手・機会から候補を出す。未知の相手の本心や、町全員の隠し値を参照しない。
2. 技能、道具、設備、費用、移動、勤務、食事・休息、世話の引継ぎ、相手の意思を確認する。欲求の高さやプレイヤーの提案で越えない条件を先に判定する。
3. 候補ごとに、複数の欲求をどれだけ満たしそうか、何を消耗しそうかを予測する。性格、価値、経験、関係、役割、習慣から重みと期待を変える。
4. 緊急性と現在の計画の継続を考慮し、近い候補から保存可能な乱数で選ぶ。最も高い欲求に常に直行する、または理由のないランダム行動へはしない。
5. 相談・準備・予約・移動・合流・実行・終了へ進む。状態が変われば、継続、分担、延期、辞退、別案を選ぶ。
6. 実際の充足と負担、相手の応答、できるようになったことを経験として残し、次の選択へ戻す。

動機、能力、機会を分ける考え方には[COM-Bの原著](https://link.springer.com/article/10.1186/1748-5908-6-42)を参照する。[R18](research-notes.md#r18-動機能力機会を分ける)は健康行動の介入設計研究であり、本作の住民AIの有効性や人間全般の欲求を実証するものではない。自律性・有能感・つながりは既存のR05、個人内の変動はR07、習慣はR08と対応づける。

## 欲求と一緒に用意する行動

既存の食事・休息・趣味・会話・制作を基盤に、次のまとまりを追加する。台詞の言い換えは新しい行動と数えず、必要条件、時間の使い方、相手への応答、世界に残る結果を変える。

| 行動のまとまり | 成立条件・選択の違い | 状態と相手への影響 | 必要な表現 |
|---|---|---|---|
| 一人で読む、散歩する、考える | 静かな場所、本人の自由時間 | 刺激や緊張から回復。つながりの不足は解消しきらない | 本・歩行・立ち止まり・姿勢 |
| 同じ場所で別々に過ごす | 二人が静かな同席を望み、席と道具がある | つながりと静けさを両立。会話を強制しない | 各自の作業、時々の視線 |
| 練習する、教わる、教える | 技能差、関心、余裕、本人が知る相手 | 上達、成功・失敗の手応え、相手の負担。後日別の人を助けうる | 手元、実演、見てから試す動き |
| 新しい試作・発見をする | 知った機会、材料、場所 | 刺激と創作の手応え。失敗すればやり直し・相談の候補 | 活動別の道具と変化する作りかけ |
| 作品を見せる、感想を聞く | 実在する作品、聞く意思、関係と場所 | 承認、緊張、期待との違い。同じ評価でも受け止めが異なる | 渡す・見る・指す・相づち |
| 相談する、慰める、差し入れる | 困り事を実際に知り、相手が支援を望む | 安心とつながり。助ける側の時間・資源も使う | 話す番、聞く番、受け渡し |
| 頼みを断る、分担・日時を相談する | 現在の余裕、責任、意思 | 自律性を保ち、別の人や後日の機会へつながる | ためらい、返答、次の予定 |
| 集まりを開く、参加を控える、途中で帰る | 主催者、複数人の席・予定・参加意思 | 新しい出会い、刺激、疲労、翌日の静かな過ごし方 | 集団の配置、合流と退出 |
| 二人で過ごす、デートへ誘う、関係を話す | 相互の関心、境界、予定、個別の同意 | 相手別の親密さ、喜び、緊張、保留や距離の取り直し | 二人の向き、視線、表情、返答 |
| 成人同士で親密な時間を過ごす、延期する | 成人、双方の意思、私的な場所、責任と時間 | 各人の動機と受け止めを更新。同意や恋愛感情を自動加算しない | 非露骨な場面の省略と、前後の状態・返答 |

各定義には、目的・役割、対象となる欲求、前提、場所・道具、所要時間、相手への相談、効果の適用時期、失敗・中断、再考の間隔、対応する動作を持たせる。複数行動の同時進行には姿勢・手・視線・席などの使用競合も定義する。

実際の動きと物の状態は[モーションと街の相互作用の設計](motion-and-world-interaction.md)へ接続する。欲求を回復する行動名が選ばれただけでは完成にせず、対象へ近づき、物や相手に働きかけ、結果が成立し、片付けて離れるところまで対応づける。

たとえば、孤独だが接客で疲れた智は、集まりより親しい一人との静かな同席を選ぶ。そこで咲の作品を知り、翌日に余裕ができた智が仕上げを申し出る場合がある。咲は承認だけでなく自分で完成させたい思いもあるため、全部を任せる、少し教わる、今回は断るという違いが生じる。この結末を固定イベントにせず、状態・知識・関係・設備を変えて続きが変わるか調べる。

## 公開する情報と、行動から分かる内面

HUDの基本は現在の元気・満腹・交流を保つ。細かい心理値を全部追加して画面を埋めない。本人が言った「今日は静かに過ごしたい」、繰り返す習慣、予定の変化、作品、誰に会いに行くかを観察の手掛かりにする。

性欲や相手への私的な関心を数値、ツールチップ、万能な提案理由に表示しない。他の住民は、本人が表した意思や観察した出来事からだけ関係を理解する。内部の比較用には選択理由と状態変化を記録できるが、通常の人物手帳・うわさ・共有用画像とは分ける。プレイヤーの提案は選択の機会を作り、隠し値を直接操作するボタンにはしない。

## 実装する順序と、確かめること

| 段階 | 実装と一緒に揃えるもの | 次へ進む条件 |
|---|---|---|
| v0.6 前半 | 既存4欲求を共通管理し、自律性・有能感・刺激への欲求と短期気分を追加。一人の回復、静かな同席、練習・教え合いを接続 | 特定の欲求だけを変えた比較で、実行と回復・負担が変わる。既存の日課・責任・保存を損なわない |
| v0.6 後半〜v0.7 | 安心、承認、貢献、相手別の親密さ、成人の性欲を追加。作品の共有、相談、関係の相談、合意した私的な時間を用意 | 双方の異なる意思と結果を扱い、断る・別案・中断が機能する。隠し値が他者や公開UIへ漏れない |
| v0.7〜v0.8 | 第三者の紹介、集まり、助け合い、予定の修復と結ぶ。12人で成立させてから16/24人へ | 違う人の欲求や経験が、次の人の機会を変える。人口だけで同じ誘いの反復や生活の欠落が増えない |
| v0.9 | 反復経験から習慣・価値・願い・関係の長期変化へ。身体の快適さは設備と体験を見て採否を決める | 同じ年月でも実際の経験の違いが、続く習慣・作品・人生へ残る |

受け入れには以下を使い、項目や行動の数だけで人間らしさ・面白さを判断しない。

- 同じ人物・seed・予定で一つの欲求だけを高低に変え、選択、実際の行動時間、充足と負担を比べる。同じ欲求でも性格・相手・場所を変えると、理由のある違いが出るか調べる。
- 孤独と静けさ、親密さと自律性などを同時に高くする。相反する状態を一律に平均せず、静かな同席や延期などの候補が機能するか確かめる。
- 合意あり／辞退、未知の相手、勤務・食事・休息・世話の最中、到着前・途中終了を比べる。実参加前に充足を付けず、断りを上書きせず、引継ぎのない責任放棄を作らない。
- 17歳／18歳、成長モデルの切替、保存・再開で成人向けの状態と候補の対象を確認する。隠し状態が、未観測の他者の知識、公開HUD、通常の手帳へ出ないことを確認する。
- 連続した実行と中断で更新量を確認し、同じ完了イベントを二度受けても効果が二重に付かないこと、現行形式の保存後も状態・計画・乱数が再現することを確認する。旧開発版との保存互換は要求しない。
- まず通常の12人・3seed・3代表日を無介入で比較し、行動の偏り、拒否後の誘い直し、睡眠・食事・仕事・支援の脱落、充足不能な欲求を調べる。条件を固定した比較と自然経過を混同しない。
- 各追加状態を外す比較で、それが実際に選択や結果へ寄与しているか調べる。変化のない飾りの値や、必ず同じ行動へ向かわせる値は見直す。
- 人による試遊で「この人は何を望んでいそうか」「なぜ前と違う選択をしたか」「次に誰へどう働きかけたいか」を聞く。隠し値の正確な当て物にはせず、複数の解釈と人物への関心が残るかを見る。

実装・比較結果が揃うまでは「欲求を思考ルーチンへ反映した」と記録しない。新しい状態は保存・定義・選択・結果・表示・動作の一式で導入する。
