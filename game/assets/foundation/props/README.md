# HouseholdProps

Native Godot geometry in `game/foundation/household_props.gd`; no new paid/generated assets. Cloth uses the existing foundation linen shader. The older `PR_BreadPlate.glb` contains already baked bread, so it is deliberately not used for an uncooked or generic meal. Existing `PR_Mug.glb` remains authored HomeArt decoration, not a newly produced drink.

`configure(house, life, actors)` binds one layer per house. `sync(delta=0)` reads inventory, real started jobs, machine inflight stock, biography possessions and actually completed project artifacts. It changes no source time, need, stock, job, body root or gameplay effect. `objects`/`manifest()` expose a unique visual source slot, `represented_quantity(type,key)` exposes its source quantity, and `pose_for(actor)` exposes held tray/basket transforms and grip points for later body/finger integration.

Inventory IDs are category-plus-index slots. Job IDs are job-plus-index slots with the controller's stable `batch_id`. They are not persistent individual-item provenance across the quantity model. A cancelled held batch continues following its actual holder; assignment to its successor does not move it. The controller's actual pickup/put-down changes holder/container. JSON resume reconstructs visuals from those same sources and needs no visual save state.

Job records retain the controller's exact `container`, `source_holder` and `last_fixture`; `display_fixture` describes their presentation sublocation. `holder` is the direct hand attachment (payload objects can inherit a held tray/basket parent). A missing hand attachment never clears or rewrites the controller's actual holder.

Towels are textile subsets, and machine contents are inflight inventory rather than a second stock. Unfinished eating owns its one plate. Only completed cooking exposes prepared food; plating/serving owns the corresponding finite dishes. Bath towels follow the controller's real basket/holder; a missing hand socket hides a held towel with diagnostics rather than floating it beside a resident. Body wiping and grip pose remain unaccepted. Counts beyond 24 per source use an explicitly diagnosed aggregate bundle; this is not accepted individual-volume presentation.

The plan's resource `support_point` metadata supplies actual counter, sink-basin, shelf and towel-basket heights. `put_down_kinds` is enforced by HouseholdDay, not by this view. A resting batch uses its exact recorded `position`. Fixed HomeArt linen stock is replaced only within `linen_storage`/`washer`; repeated autogenerated node names are handled by their scoped linen material. Books, wall pictures, furniture and curtains are preserved, and removing/reconfiguring this view restores its own hidden artwork.

Held objects are children of `BoneAttachment3D` with `override_pose=false`. `skeleton_updated` captures the post-modifier transform. A palm is estimated from the hand/finger rest bones; this does not certify skin contact. `pose_for().pose_accepted` remains false: supporting-hand IK, grip/finger contact, locomotion with a load, appliance interaction, controlled setting-down and actual rendered carrying must still be integrated and reviewed by the root task. The coarse logical held batch position is not used to reposition a motor.

The focused test exercises real source transitions and a real skeleton modifier under controlled positions. It is not natural walking/gameplay or human playtest evidence. GPU evidence is pending the shared rendering slot.
